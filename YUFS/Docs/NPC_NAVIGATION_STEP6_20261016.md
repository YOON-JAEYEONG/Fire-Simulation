# NPC 경로 탐색 6단계 — 대피 성공 판정의 물리 조건

2026-10-16. 사용자가 직접 에디터를 확인하기 어려운 상황에서 맡긴 후속 디버깅이다. 이번 범위는 출구의 잘못된 성공 판정이다. 프로젝트는 `C:/Users/ACSLAB4/Documents/Codex/Fire-Navigation-1008/YUFS/YUFS.uproject`, 로컬 브랜치는 `codex/merged-navigation-completion`이다. 기존 1~5단계를 보존했으며 커밋/푸시는 하지 않았다.

## 수정 전에 재현한 문제

기존 IsAtValidExit는 유효한 출구의 존재와 NPC 중심까지의 거리만 검사했다. 물리 월드에서 벽, 닫힌 문, 부분 개방 중인 문이 사이에 있어도 성공으로 처리되는 것을 자동 검사에서 확인했다. 출구 아래의 바닥과 다른 높이의 판 위에 있어도 거리 안이면 성공했고, 바닥을 제거해도 성공했다. NPC 자체의 학습 종료 판정은 150cm를 고정 사용하여 컨트롤러의 설정 반경과 달라질 수 있었다. 수정 전 3개 재현 검사가 의도한 조건에서 실패했다.

일반적인 350cm 층간 높이는 기존 3차원 거리 검사로도 배제된다. 모든 2층 NPC가 1층 출구로 잘못 계산됐다는 주장은 아니다. 재현한 것은 기존 반경 안에 들어오는 가까운 다른 바닥/가림 구조의 경계 조건이다.

Main의 초기 문 시험에는 진단 스크립트의 회전 인자 오류가 있었다. 실제 Actor 회전을 확인하니 문이 서 있는 대신 바닥에 누워 있었다. 이때 성공이 잡힌 기록은 닫힌 문을 뚫은 버그의 근거로 사용하지 않는다. 원래 코드에서 잘못된 성공을 재현한 근거는 위의 물리 월드 검사다. Main의 최종 문 검사는 회전·세로 크기·손잡이 도달 조건을 명시적으로 확인하고 수정 후 닫힘/개방 판정을 검증했다.

문의 NPC는 외부 내비게이션과 정지된 이동 컴포넌트를 사용하는 고정 시험 대상이고, 경보에는 대피를 결정하도록 임시 Config를 사용했다. 이 시험은 문을 자율 발견하고 여는 능력을 평가하는 것이 아니다.

## 변경

- 성공 함수는 좌표만이 아니라 실제 Character를 받아 현재 캡슐과 이동 설정으로 검사한다. 저장된 유효 출구가 있어야 하며 기존 설정의 중심 거리 반경은 유지한다.
- 발 위치와 출구 기준점 높이가 한 발판 높이 범위를 넘어 연결되지 않으면 거부한다. 기존 로컬 이동의 바닥 연속성, 걸을 수 있는 법선, 캡슐 상승·전진·하강 여유 검사를 재사용한다. 판정 쿼리는 NPC를 이동시키지 않는다.
- 마지막에 실제로 찾은 지지 바닥 높이가 출구 기준 높이의 ±10cm 안인지도 검사한다. 이 확인이 없으면 출구 바로 위 40cm 판을 걷는 검사 결과가 출구 바닥 대신 사용될 수 있다. 출구 Actor의 위치는 **출구 바닥 기준점**이어야 한다.
- 벽/문의 물리 충돌은 유지한다. 대피 영역 분류에 한해 다른 EvacuationNPC를 쿼리에서 제외하여 출구 군중이 서로 성공을 가로막지 않게 했다. 실제 이동/복구 검사는 기본값으로 기존 NPC 충돌을 계속 포함한다. 충돌을 끄거나 순간 이동하는 변경은 없다.
- 기어가고 있으면 실제로 낮아진 캡슐을 사용한다. 낮은 통로에서 서 있는 몸은 거부하고, 실제 낮은 몸에 충분한 공간이 있으면 허용한다.
- NPC의 종료 판정과 컨트롤러의 인원 집계가 같은 함수와 같은 설정 반경을 사용한다. 기본 반경 150cm, 기본 노출/행동 설정, 출구 배치, 맵/NavMesh/화재 데이터는 바꾸지 않았다.

C++ IsAtValidExit의 인자는 FVector에서 Character 포인터로 바뀌었다. 저장소 내 호출 두 곳을 함께 수정했다. Blueprint 호출 함수가 아니므로 이 변경으로 Blueprint 에셋을 편집하지 않았다. 다른 맵의 출구 기준점이 바닥과 다르게 설정되어 있다면 그 맵의 배치를 확인해야 하며 자동 추정/이동으로 숨기지 않는다.

## 검증

UE 5.7.4 Development Editor 빌드 성공. 전체 `YUFS.NPC` 검사 **93개 성공, 실패 0개**. 기존 89개에 다음 4개를 추가했다.

- 벽/닫힌 문/부분 개방 문은 거부하고, 실제로 열린 통로는 허용한다. 다른 주민은 성공 영역을 막는 벽으로 취급하지 않으면서 실제 복구 이동에서는 충돌한다. 쿼리가 NPC 위치를 바꾸지 않는다.
- 40cm·50cm 위의 별도 지지 판을 출구 바닥으로 혼동하지 않으며, 실제 출구 바닥을 허용하고 지지 바닥이 없으면 거부한다.
- 컨트롤러의 큰 반경/작은 반경 설정을 NPC 종료 판정도 함께 따른다.
- 낮은 장애물을 서 있는 캡슐로 통과했다고 처리하지 않고, 실제 기어가기 캡슐에는 맞는 결과를 낸다.

기존 출구 없음/파괴된 출구/원점 출구 검사는 유지했다. 이제 실제 지지를 검사하므로 원점 성공 시험에도 물리 바닥과 올바른 NPC 높이를 구성했다. 위험 경로 재탐색, 노출, 기어가기, 문/소화·도움 연동, 일시정지·타임라인 검사를 포함한 전체 회귀 결과다.

저장된 Main에서 렌더링 PIE로 수정 전후 비교했다. 정상 이동 조건은 이전과 동일한 초기 XYZ에 팔레트 NPC 20명씩을 배치하고, 성향/화재의 영향을 분리하기 위해 런타임에서만 경보 응답 Config와 화재 0프레임 정지를 사용했다. 일반 시나리오의 반응 비율이나 실제 화재에서의 생존율을 바꾼 검사가 아니다. 실제 마우스로 배치한 수동 시험도 아니다.

첫 정상 두 배치는 각각 40초, 문 조건은 17초 관찰했다. 정상 배치의 초기 XYZ는 전후 일치한다. 시간이나 교착 해소가 전반적으로 개선됐다는 통계적 결론은 아니다. 닫힌 문 조건은 12초의 닫힌 상태를 확인한 뒤 열기 요청을 했고, 실제 개방 완료 후 성공이 가능해졌다.

증거는 `NavigationStep6Evidence`에 보관한다. 문 생성의 Quat/Rotator 타입 오류와 위치 인자로 인한 회전축 오류를 각각 확인/수정했다. 정상 두 배치 기록을 보존하고 잘못된 문 조건만 별도로 재실행했다. 게임 코드의 실패와 진단 스크립트 준비 오류를 구분한다. 정상 군중 두 배치와 최종 문 조건은 분리된 실행 기록이다. 전체 조건을 위한 재현 스크립트와 문 조건만 재실행하는 스크립트를 함께 보관한다.

## 한계와 다음 점검 대상

- 성공은 여전히 설정된 출구 **영역에 접근한 판정**이다. 건물 외부 경계선을 몸 전체가 넘어갔다는 판정으로 바꾼 것이 아니다. 외향 평면·완전 통과·출구 폭에 따른 새 영역을 도입하려면 출구 방향과 맵 밖 내비게이션의 별도 설정/검증이 필요하다.
- 이 변경은 현재 Main을 검증한 것이다. 모든 레거시 맵의 출구 배치, 모든 고밀도 반대 방향 유입, 잘못된 충돌/내비게이션 설정을 검증하지 않았다. 맵에서 벽의 충돌 자체가 빠져 있다면 쿼리만으로 실제 벽을 추론할 수 없다.
- 물리 통로 검사는 기존 구현처럼 약 30cm 간격의 바닥 표본과 현재 캡슐을 사용한다. 지형의 모든 아주 작은 구멍과 모든 비정상 사용자 설정을 보장하지 않는다.
- 화재 원본 물리 단위·전체 시퀀스 정합 미확인, 외부 모션 그래프 내부의 되감기, 기록 시점과 다른 일부 HUD/디버그 표시, 기존 행동 불능 숨김 정책은 남아 있다. 이번 단계와 섞어 수정하지 않았다.

검증된 범위와 남은 항목을 구분한다. 전체 프로젝트에 버그가 없다는 보증은 하지 않는다.
