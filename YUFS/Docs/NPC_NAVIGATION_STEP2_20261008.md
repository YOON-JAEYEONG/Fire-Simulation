## 재현한 원인

기존 ShouldRetryPath는 UnsafePath/HazardDataUnavailable 상태에서 프레임 번호가 달라지면 재시도 횟수 제한을 우회했다. 8fps 화재 재생에서는 같은 위험 경로를 계속 재요청할 수 있었다. 또한 ChooseKnownExit는 다른 선택 경로에서 사용하던 최근 실패 출구 목록을 건너뛰고 같은 출구에 비용만 더해 재선택했다.

1단계 검증 실행의 실제 Main 로그에서 첫 25초 동안 1번 화재의 한 NPC는 같은 위험 경로 탐색과 UnsafePath 실패를 12회 반복했다. 3번의 두 NPC도 각각 7회 탐색했다. 그 로그와 같은 배치 스크립트를 이번 비교에 사용했다.

## 구현

- 최종 NavMesh 경로가 인지한 연기·열을 가로질러 거부되면 위험 지점 옆 ±200/±400cm의 네 후보를 검사한다. 각각 현재 층의 NavMesh에 투영하고, 실제 두 구간의 경로를 구한 뒤 연결된 전체 경로를 다시 위험 평가한다. 부분 경로/위험한 최종 경로는 채택하지 않는다. 네 후보 중 길이와 위험 비용이 낮은 경로를 사용한다.
- 이 후보 검사로 해결되지 않으면 거부한 경로와 위험 관측 지점을 보관한다. 새 화재 프레임 자체는 재시도를 허용하지 않는다. 기본 2초 간격으로 위험 구간을 재평가한다.
- 위험 관측 지점이 다시 관측되고 현재 경로 평가가 허용 가능한 상태가 되었거나, NPC의 접근 위치가 100cm 이상 달라졌을 때 재탐색을 허용한다. 데이터 Loading은 허용 근거가 아니다. 같은 목적지 재요청도 이 대기를 우회하지 않는다.
- 개인 기억에 최근 관측한 셀의 존재를 별도로 기록한다. 값이 0인 관측도 기록하므로, 재시도 조건에서는 실제로 연기가 사라졌다는 관측과 기억이 만료된 상태를 구분한다. 이 셀 집합도 복사된 불변 스냅샷으로 전달하며 초기화/좌표 변경/만료 시 함께 정리한다. 위험 값 저장소를 새로 병렬 구현한 것은 아니다.
- 최근 실패한 출구를 가장 가까운 출구/익숙한 출구 선택에서도 제외한다. 대안이 없으면 거부 상태를 유지하며 기다린다. 실패 기록만 지워서 즉시 같은 길을 다시 요청하는 것을 막았다.
- 호환되는 기본 모션에서는 위험 경로 대기 중 정지한 NPC를 WaitForInfo/Idle로 표현한다. 대피 결정은 유지하며 기어가기·행동 불능 애니메이션의 우선순위도 유지한다. 외부 모션 담당 모드는 기존 소유권을 유지한다.
- 진단에 request, waitingSafe, exposureScale을 추가했다.

우회 판단은 개인이 관측한 위험에 기반한다. 이동 중 새 위험을 감지하면 기존 재평가가 적용된다. 네 개의 근처 후보는 모든 가능한 전역 경로를 완전 탐색하는 알고리즘이 아니므로, 위험 구간이 넓거나 대안이 없으면 대기가 남을 수 있다.

## 연기 노출 시간

사용자가 60초 시뮬레이션 안에서 기어가기와 행동 불능도 관찰할 수 있게 시간을 줄여 달라고 요청했다.

기존 누적률 0.008/초, CrawlThreshold 0.6, IncapacitationThreshold 0.9는 유지하고 BehaviorConfig에 SmokeExposureTimeScale을 추가했다. 기본값 3이다. 농도에 비례한 누적만 이 배율을 적용하며 기존 신선한 공기 회복률은 유지한다.

| 일정한 자기 위치 연기 농도 | 기어가기 기준 시간 | 행동 불능 기준 시간 |
| --- | ---: | ---: |
| 1.0, 배율 3 (새 기본) | 25초 | 37.5초 |
| 0.5, 배율 3 | 50초 | 75초 |
| 1.0, 배율 1 (기존 방식) | 75초 | 112.5초 |

초기 노출 0에서 계속 같은 농도에 머무르는 계산이다. 연기를 늦게 만나거나 빨리 탈출하면 상태 전환도 늦어지거나 발생하지 않는다. 시연 시간 압축이며 실제 인체 독성·생존 시간의 물리적 보정값이 아니다. 배율 1로 이전 타이밍을 복원할 수 있다. 공유 DataAsset을 실행 중에 변경하지 않는다.

## 검증

최종 빌드 성공. 전체 `YUFS.NPC` 테스트 76개 성공, 실패 0개. 새 회귀 테스트는 다음을 확인한다:

- 동일 위험의 프레임 진행/중복 목적지 요청이 대기를 우회하지 않음.
- 미관측/만료된 기억이 위험 해소로 사용되지 않음; 실제 관측된 해소는 재탐색을 허용함.
- 데이터 Loading에서 위험 경로를 허용하지 않음.
- 실패한 출구 대신 다른 출구를 선택하고, 모두 제외되면 대기하며, 만료 후 재평가함.
- 농도 1의 25/37.5초 전환, 농도 0.5의 더 느린 전환, 배율 1의 기존 시간, 연기 없는 60초의 노출 0 유지.

실제 저장된 Main 렌더링 PIE에서 화재 1/2/3을 각각 54초 실행했다. 각 실행은 이전과 같은 네 지점의 팔레트 클래스 NPC를 일시적으로 생성했다. 런타임 검사에서만 화재 지연 0을 사용했고 맵에 저장하지 않았다. NPC 구성에서 기본 누적률 0.008과 새 배율 3이 적용됨을 직접 읽었다.

첫 25초의 NavMesh 탐색 요청 수 비교:

| 사례 | 1단계 코드 | 2단계 코드 |
| --- | ---: | ---: |
| 화재 1 / NPC 0 | 12회 (UnsafePath 12회) | 3회 (UnsafePath 0회) |

새 실행에서 근처 우회 채택을 4회 기록했다(화재 1과 3). 처음부터 위험 안에 있던 경우에는 기존 위험 영역에서 빠져나오는 허용 규칙을 유지한다. 따라서 경로 최대 연기값이 높다는 사실만으로 금지 경로를 강제로 통과시킨 것은 아니다.

54초 시점에 화재 1/2는 배치한 네 NPC 모두 유효 출구에 도착했다. 화재 3은 두 명이 도착했고 두 명은 위험 경로 대기였다. 대기 NPC의 request 값은 각각 3/2로 유지됐고 애니메이션은 Idle이었다. 이 배치의 결과이며 전원 탈출이나 모든 군중 병목 해소를 보장하지 않는다. 비교 전후에는 노출 배율도 바뀌었으므로 일반적인 대피율 개선 통계로 사용하지 않는다.

별도 노출 비교 검사는 Main의 실제 화재 1 데이터를 480프레임에서 정지시켰다. 두 NPC의 이동을 외부 내비게이션/MOVE_NONE으로 제한한 **통제된 노출 검사**이며 일반 대피 결과가 아니다. 상태를 강제 설정하지 않고 기존 감지와 상태머신으로 누적했다. 실제 자기 위치 농도는 둘 다 254/255≈0.996이었다.

- 배율 3 NPC: 약 26초의 첫 기록에서 Crawling, Crawling__1__Anim 활성, 속도 제한 80cm/s. 약 38초에서 Incapacitated, Dying 활성, 속도 제한 0.
- 배율 1 비교 NPC: 45초까지 Evacuating이며 누적 노출 약 0.359; 기어가기/행동 불능 없음.
- 프레임 480 유지 여부를 스크립트가 매 기록에서 검사했다. 최초 검사에서는 화재 시작 시 프레임이 리셋돼 일정 농도가 아니었고, FireActive 이후 프레임을 고정해 다시 검증한 최종 기록을 사용했다.

이 검사는 기존 애니메이션 연결과 속도 제한을 확인한다. 실제 낮아진 호흡 높이/캡슐·기어가기 경로 통과 검증은 예정된 후속 단계에 남아 있다. 실제 마우스 배치로 수행한 수동 검사라고 주장하지 않는다.
