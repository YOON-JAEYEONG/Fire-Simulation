# NPC 경로 탐색 8단계 — 연기 누적에 따른 시야 감쇠

2026-10-17. 프로젝트: `C:/Users/ACSLAB4/Documents/Codex/Fire-Navigation-1008/YUFS/YUFS.uproject`. 로컬 브랜치: `codex/merged-navigation-completion`. 기존 1~7단계를 보존했으며 커밋/푸시하지 않았다.

## 범위와 재현

이번 단계는 광학 위험 감지의 일관성이다. 개인별 출구 기억까지 동시에 바꾸면 출구를 모르는 NPC의 탐색/안내 수신도 함께 설계해야 하므로 별도로 남겼다. 이 범위 분리는 작업 중 사용자에게 설명했다. 현재 `ChooseKnownExit`와 `TryGetNearestKnownExit`는 여전히 레벨 전체 출구 목록을 사용한다. 이것이 이번에 해결됐다고 해석하면 안 된다.

수정 전 두 개의 회귀 검사에서 다음을 재현했다.

- NPC 앞 100~400cm의 두꺼운 연기가 있어도, 600~700cm의 고온 영역을 약 0.797의 시각 단서로 감지했다.
- 그 뒤의 셀을 관찰했다고 기록하여 경로 지식에 열 1.0이 들어갔다. 연기에 가려진 후에도 관측 시각을 계속 갱신하여, 기존 30초 기억 만료 규칙으로도 지워지지 않았다.

## 수정

- 시선 구간의 정규화 연기 농도와 구간 길이를 누적한다. 각 구간에서 투과도를 감소시키고, 설정된 임계값 아래로 내려가면 더 먼 셀을 새로 관찰하지 않는다. 범위 안에서 보이는 연기 자체는 계속 감지한다. 시각적 열 단서는 투과도에 따라 약해진다.
- 기본 설정은 `SmokeSightAttenuationPerMeter=1.2`, `MinimumSightTransmission=0.15`다. 투과도는 `exp(-1.2 * 누적(정규화 농도 × 거리[m]))` 형태다. **원본 BIN의 소광 계수를 확인한 물리 모델이 아니라 시뮬레이션용 인지 보정값**이다. 설정값 0은 같은 기하 조건에서 감쇠를 끈 비교 모드다.
- 기존 벽/바닥 충돌 검사를 유지한다. 설정된 최대 표본 간격에 더해 월드 복셀 간격의 절반을 참고하여 짧은 연기층을 건너뛰는 일을 줄인다. 표본 간격 하한 5cm/광선당 최대 1024회가 있으므로 모든 크기의 미세 구조를 보장하지 않는다.
- 가려진 먼 셀은 새로 관찰하거나 안전하다고 갱신하지 않는다. 전에 본 위험은 즉시 잊지 않고 기존 기억 만료 규칙을 따른다.
- 소화 대상 등의 위험 지점을 읽는 `SampleObservedHazard`도 같은 시선 적분, 거리, 수평 시야각과 벽 검사를 사용한다. 가려진 지점을 직접 조회하여 시야 제한을 우회하지 못한다. 보이는 지점의 출력/기억은 실제 BIN 원시 정규화 값을 보존하며, 시각 단서의 약화값으로 원본 위험도를 덮어쓰지 않는다.
- 현재 위치의 연기/열과 누적 노출 계산은 그대로다. 근접 열 감지는 기존 반경의 국소 감각으로 유지하며 광학 감쇠를 적용하지 않는다. 이 국소 감지도 벽/바닥에 막힌다. 실제 열 전달 물리를 추가한 것은 아니다.
- 실제 낮아진 눈높이를 사용하므로 기어가서 아래의 맑은 층을 보게 되면 시야도 달라진다. 아래층까지 연기가 차면 시야와 자기 위치 노출은 계속 나쁘다.
- `sightCm`, `sightTransmission`, `sightDataComplete`를 기존 위험 진단에 추가했다. 마지막 값은 검사한 가시 구간의 데이터 가용성이다. 원본 좌표/시간/물리 단위가 검증됐다는 뜻이 아니다. 미로딩/미관측 값 0을 확인된 맑은 공기라고 인증하지 않는다.

## 검증

UE 5.7.4 Development Editor 빌드 성공. 전체 `YUFS.NPC` 검사 **102개 성공, 실패 0개**. 이전 96개에 다음 6개를 추가했다.

1. 두꺼운 연기가 먼 고온 영역과 새로운 셀 관측을 막되 앞쪽 연기는 보이는지 검사한다.
2. 가려지기 전에 본 위험은 기억하지만 보이지 않는 동안 관측 시각이 갱신되지 않고 만료되는지 검사한다.
3. 20cm의 얇은 연기층이 거친 80cm 설정 사이에서 사라지지 않는지, 두께에 따라 효과가 달라지고 감쇠 0 비교 모드가 작동하는지 검사한다.
4. 직접 위험 지점 조회도 연기, 수평 시야각과 벽을 따르며, 실제로 보일 때만 원시 위험 값을 기록하는지 검사한다.
5. 실제 낮은 캡슐/눈높이에서 하부 맑은 층의 시야가 늘고, 자기 위치 농도와 근접 열 감지는 광학 차단과 독립적으로 유지되는지 검사한다.
6. 미로딩/개인 미관측 데이터로 완전한 광학 가용성을 인증하거나 새 위험 관측을 기록하지 않는지 검사한다.

렌더링 Main PIE에서는 실제 팔레트 Blueprint NPC 두 명을 같은 위치 `(1200,-300,440)`에 임시 생성했다. 이동을 멈추고, 각각 감쇠 0과 1.2를 사용하여 실제 화재 데이터 3종의 480프레임에서 8방향을 비교했다. 시점 고정 실험 동안 자세가 달라지지 않도록 노출 배율만 런타임에서 1로 통일했다. 맵/애셋/기본 노출 배율 3은 바꾸지 않았다.

별도의 네 번째 Main 실행에서는 기본 인지/이동 구성의 NPC 4명을 실제 NavMesh 위에 배치하고 1번 화재를 25초간 정상 진행했다. 검사에서만 화재 지연을 0으로 했으며 조기 대피 성향을 강제하지 않았다. 네 NPC 모두 초기 위치에서 약 521~885cm 변위가 있었고 실제 화재 프레임도 진행했다. 이는 새로운 감지가 모든 NPC를 정지시키지 않는다는 제한된 회귀 확인이며, 전원 대피 성공이나 정상 화재 생존율을 검증한 통계는 아니다.

실행 스크립트/원본 결과/로그/소스 및 DLL 해시는 `NavigationStep8Evidence`에 보관한다. 자동 렌더링 PIE이며 사람의 화면 관찰이나 카메라 픽셀 인식을 의미하지 않는다.

최종 전체 검사와 Main 진단은 모두 반환 코드 0으로 종료했고 에디터 종료를 확인했다. 기존 시작/종료 메시지가 남으므로 전체 엔진 로그가 무오류라는 뜻은 아니다.

## 남은 항목

- 개인별 출구 기억, 출구를 모를 때의 탐색, 군중/공식 안내에 따른 출구 지식 획득은 다음 단계다. 건물 전체 출구 정보를 현재 후보로 쓰는 문제는 남아 있다.
- 이번에 공통 제한을 적용한 상호작용 API는 **위험 지점의 연기/열 관측**이다. 소화기·문·사람·군중의 일반 발견 코드는 각 담당의 기존 거리/가림 정책을 유지한다. 모든 사회/물체 감지가 연기 시야 모델로 통합됐다고 주장하지 않는다.
- 가까운 신체/주변 열 감지와 국소 셀 기억은 유지하므로, 광학 차단 거리 밖의 모든 셀이 무조건 미관측인 것은 아니다. 원격 시각 탐지와 근접 국소 감각을 구분한다.
- 기존 위험 회피는 개인 기억과 재탐색을 사용한다. 시야가 줄어도 이미 아는 경로가 즉시 사라지는 것은 아니며, 이 변경이 연기 속 진입을 전부 금지하는 것은 아니다. 안전 경로가 없거나 처음 보는 구간에 진입했다가 위험을 인식하는 경우는 별도로 판단한다.
- 정규화 BIN과 실제 소광/온도/유해 가스 단위, 화면 SVT의 전체 시퀀스 정합은 미확인이다. `bDatasetAlignmentConfirmed=false`를 유지한다. 예시 가시거리를 실측값으로 제시하지 않는다.
- 28개 ONNX 입력 차원, 기본 노출/성향/기록 시간, 맵/블루프린트/원본 데이터는 바꾸지 않았다. 모든 고밀도 흐름과 3종의 정상 전개 전체 비교는 남아 있다.
- 기존 엔진 시작 `Condition failed`/선택 전 기본 BIN 부재와 RiderLink 종료 메시지가 남을 수 있다. 검사 결과와 엔진 로그 전체의 무오류 여부는 구분한다.
