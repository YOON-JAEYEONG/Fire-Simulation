# NPC 경로 탐색 5단계 — 일시정지와 팀 행동의 기록 재생

2026-10-16. 프로젝트: `C:/Users/ACSLAB4/Documents/Codex/Fire-Navigation-1008/YUFS/YUFS.uproject`. 작업 브랜치: `codex/merged-navigation-completion`, `merge_JJW_Kim_Eung_Gang@83cb710` 기반. 기존 1~4단계의 로컬 변경을 보존했다. 커밋/푸시는 하지 않았다.

## 재현한 문제

수정 전 코드에 통합 재현 검사 4개를 추가했다. 일시정지에서 메시의 애니메이션이 멈추지 않는 것, 관찰 모드에서 실제 상호작용 클립/재생 위치 대신 정책 행동의 모션이 적용되는 것, 되감아도 문과 소화기가 마지막 모습으로 남는 것을 확인했다. 시작되지 않은 테스트 월드의 틱은 실제 플레이와 다르므로 일시정지 검사의 시작 틱 상태는 이후 명시적으로 설정했다. 수정 전 로그의 모든 실패 항목을 별도의 게임 버그로 계산하지 않는다.

## 구현

- **일시정지:** NPC 판단, 이동 컴포넌트, 경로 재검사 시계, 메시 애니메이션을 함께 멈춘다. 이미 계산 중인 경로 요청은 취소하여 오래된 결과가 정지 중 적용되지 않게 한다. 진행 중인 소화/도움/문 행동의 예약과 노출 값은 보존한다. 문 자체는 기존 시뮬레이션 일시정지 검사를 유지한다.
- **재개:** 이전에 켜져 있던 틱과 애니메이션 정지 플래그만 복원한다. 외부 담당자가 꺼 둔 이동/경로 처리까지 강제로 켜지 않는다. 반복 Pause/Resume은 원래 상태를 덮어쓰지 않는다. 이동 모드를 보존하므로 낙하/기어가기 상태를 무조건 Walking으로 바꾸지 않는다.
- **모션 기록:** 기본 네이티브 애니메이션 담당이 재생한 실제 클립, 재생 위치, 속도, 반복 여부를 저장한다. 정책 행동이 Idle이어도 실제로 소화·손 뻗기·대화 모션을 사용했다면 그 클립을 관찰 시점에 복원한다. 기어가기 충돌/호흡 높이 기록은 4단계 구현을 유지한다.
- **관찰:** AI/이동/경로 시계를 정지하고 저장된 모션 위치만 적용한다. 독립된 실시간 모션 시계를 돌리지 않으며 애니메이션 알림으로 실제 행동을 다시 실행하지 않는다. 화재도 관찰 시계가 선택한 기록 프레임을 사용한다.
- **문과 소화기:** 문 열림 정도·방향·가시성, 소화기 위치·상태·남은 약제·분사 표시 형상을 기록한다. 되감기는 실제 문 조작/소화 함수를 재실행하지 않는다. 관찰용 소화기에는 실제 소유자/예약이 없고 새 예약·분사 실행·약제 소모를 거부한다. 과거에 없던 런타임 개체는 숨기며, 해당 시점에 없는 문은 충돌도 끈다.
- **외부 모션:** 외부 Animation Blueprint를 네이티브 클립 재생기로 교체하지 않는다. 관찰 중에는 마지막 외부 자세를 멈춘다. 외부 그래프 내부 상태/블렌드/몽타주를 과거 시점의 자세로 완전히 복원하는 기능까지 구현한 것은 아니다.
- `GetCurrentReviewFrameSnapshot()`은 현재 표시 중인 정확한 기록 프레임을 읽기 전용으로 제공한다. 관찰 중의 원래 AI 상태와 기록된 표시 상태를 혼동하지 않기 위한 진단 API다.

## 검증

UE 5.7.4 Development Editor 빌드 성공. 최종 전체 `YUFS.NPC` 자동 검사는 **89개 성공, 실패 0개**이다. 이전 83개에 다음 6개를 추가했다.

1. 반복 Pause/Resume에서 판단·모션·경로 시계의 동시 정지/복원과 낙하 모드 보존.
2. 외부 담당의 비활성 틱/기존 애니메이션 정지 상태를 유지하며 외부 모션 모드를 교체하지 않음.
3. 정책 행동과 다른 실제 상호작용 클립 및 재생 위치를 기록/되감기하고, 관찰 틱이 이를 덮어쓰지 않음.
4. 소화기 위치·분사 상태·약제 표시 복원, 소유권과 새 예약/소모 방지.
5. 닫힌 문/열린 문 되감기, 관찰 중 새 문 조작과 자율 열림 방지.
6. 기어가기 일시정지/재개에서 낮은 캡슐, 발 위치, 이동 모드, 속도를 보존함.

별도로 저장된 **Main의 렌더링 PIE**에서 실제 팔레트 BP NPC 두 명, 임시 문/소화기, 실제 화재 재생을 사용했다. 이 검사는 수동 마우스 조작 시험이 아니다. 다음 설정은 검사를 위한 런타임 값이며 맵에 저장하지 않았다.

- 기록 길이 12초, 화재 지연 0초. 기본 60초 기록 길이와 기본 시나리오 설정은 변경하지 않았다.
- 한 NPC에게 명시적 소화 모션 시연을 요청했다. 자율 화재 발견/소화 성공 실험이 아니며 실제 화재 데이터를 소화 효과로 바꾸거나 성공 근거를 만들지 않았다.
- 다른 NPC는 문 개방을 위한 고정 사용자였다. 해당 이동 컴포넌트만 틱을 끄고 외부 내비게이션을 사용했다. 일반 NPC 이동을 제자리 모션으로 바꾼 것이 아니다.

실행 중 Pause를 두 번 누른 뒤 2초 동안 시뮬레이션 시간, 화재 프레임, NPC 위치, 클립 위치, 소화기 소유자/위치/약제, 문 각도가 변하지 않는 것을 검사했다. Resume 후 남은 동작과 기록이 진행되었다. 자동 관찰 전환 후 5초 시점으로 되감아 실제 클립·재생 위치·문 열림·소화기 상태·화재 프레임이 선택된 기록 프레임과 일치하는지 대조했다. 관찰 일시정지 2초 동안 모습이 유지되었고, 처음으로 되감아 재생하면 관찰 시계가 진행되었다.

Stop은 기존대로 Main을 다시 연다. 새 컨트롤러가 WaitingToStart/시간 0으로 시작하고, 새 NPC가 노출 0·서 있는 캡슐·애니메이션 비정지 상태이며, 기존 소화기에 예약이 없는 것을 검사했다. 두 번째 Start에서도 FireActive로 진행했다. 이 초기화 검사는 이전 AI 상태로부터 재시뮬레이션하는 기능이 아니다. 런타임 팔레트 배치는 Stop의 레벨 재로딩 후 사라지는 기존 동작을 유지한다.

증거와 재현 스크립트: `NavigationStep5Evidence`. 엔진 원본 로그: 원래 채팅 작업 폴더의 `work/nav1016-*`.

최종 렌더링 검사 결과는 complete=true, Python 오류 없음, 에디터 종료 로그 확인이다. 프로세스 반환 코드는 1이었다. 기존 시작 단계의 Condition failed/기본 smoke_data.bin 부재 메시지와 종료 단계 RiderLink invalid socket 메시지가 있으므로 엔진 로그 전체가 깨끗하다고 보고하지 않는다. 선택된 실제 화재 재생과 2회차 시작은 검사를 통과했다. 진단 에디터는 종료했다.

## 범위와 남은 점

- 저장된 시점을 보여주는 관찰 기능이다. 과거 시점부터 인지·개인 기억·학습 상태를 복원하여 새로운 분기로 실행하는 기능은 아니다. 관찰을 끝내고 새로 실행하려면 기존 Stop/재시작 경로를 사용한다.
- 기본 기록 간격은 0.25초이고 최근접 프레임을 적용한다. 프레임 사이 움직임 보간, 완전히 부드러운 영상 녹화, 소리/입자/모든 외부 Animation Blueprint 상태의 재생을 보장하지 않는다.
- 문/소화기/NPC는 같은 월드에 남아 있는 개체를 이름으로 찾는다. 기록 이후 파괴된 개체를 새로 만들어 복원하는 범용 리플레이 시스템은 아니다. 여러 도움 행동의 복합 군중 상황을 수동 플레이로 전부 검증한 것도 아니다.
- 기존 결과 집계/출구 영역 판정/행동 불능 NPC 숨김 정책, 원래 AI를 표시하는 일반 디버그 값은 유지한다. 이 단계는 모든 타임라인 HUD와 외부 디버그 표시를 기록 시점 기준으로 바꾼 작업이 아니다.
- 화재 BIN/VDB의 물리 단위·원본 변환 기준·전체 시간 정합은 여전히 미확인이고 `bDatasetAlignmentConfirmed=false`를 유지한다. 자율 소화의 물리적 효과나 모든 NPC의 탈출을 보증하지 않는다. 고밀도 맞은편 통행과 비정상 맵/NavMesh 조건도 별도의 검증 범위다.
