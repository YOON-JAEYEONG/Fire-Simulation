## 실제 재현한 문제

병합본은 SVT 방식으로 이미 보정된 Main에도 1번 화재의 볼륨 Transform을 공통 기준으로 적용했다. 3번의 BIN→SVT 보정/임포트 변환에 1번의 위치·크기를 섞어 감지 영역이 아래쪽으로 이동했다.

3번의 수정 전 BIN 높이 영역은 -210.4~453.6cm였다. 같은 2층 NPC 눈 높이 504cm가 OutsideDomain으로 반환돼 연기 0이 되었다. 1층 역시 잘못된 셀을 읽었다. 실제 저장된 Main의 렌더링 PIE에서 0→1→2→0 옵션 전환과 프레임 0/100/480/750/996 조회로 재현했다. 진단용 NPC는 움직이지 않도록 한 임시 샘플러이며 맵에 저장하지 않았다.

프레임 getter도 매니저의 이전 Tick에 저장된 프레임을 반환했다. Seek 직후 매니저 Tick 전에는 100/480으로 이동해도 0을 반환하는 것을 회귀 테스트에서 재현했다. 이는 실제 재생의 컴포넌트/NPC Tick 순서에 따른 지연도 허용하는 코드였다.

## 수정

- 명시적 BIN→SVT 보정이 있으면 선택한 화재의 프레임 변환과 실제 볼륨 컴포넌트 Transform을 사용한다. 다른 화재의 legacy 공통 기준을 섞지 않는다.
- 좌표 보정이 없는 legacy 데이터의 공통 기준 기능은 유지한다. 좌표 모드별 동작을 진단에 DatasetVolume / LegacyWorldAnchored / FollowsVolume으로 구분했다.
- NPC가 요청하는 현재 BIN 프레임은 그 순간의 실제 소수점 재생 프레임에 비율·오프셋을 적용한 뒤 내림한다. 이전 스트리밍 커서를 반환하지 않는다.
- 매핑된 프레임이 음수/범위 밖이거나 데이터가 없으면 유효한 안전 프레임으로 클램프하지 않는다. 필요한 BIN 프레임이 아직 안 읽혔으면 기존 Loading 상태를 사용한다.
- 진단에는 현재 판정 프레임, 스트리밍 커서 cachedFrame, 소수점 visualTimeFrame을 각각 기록한다. perceptionFrame은 NPC의 주기적 인지 캐시이므로 현재 프레임과 다를 수 있다.

이번에는 데이터별 경험적 원점, NPC 성향, 경로 비용, 노출 기준, 60초 종료, 맵·머티리얼·원본 BIN을 변경하지 않았다.

## 빌드·테스트·실제 재생

UE 5.7.4 Development Editor / Win64 최종 빌드 성공. `YUFS.NPC.Navigation.Hazard` 테스트 7개 통과. 신규 테스트는 화재별 SVT 보정/legacy 기준 우선순위, 2층 샘플, 매니저 Tick 전 Seek, 소수점 프레임 비율, 음수·종료 후 프레임을 포함한다. 기존 좌표/층·연기/열 경로·Detour·개인 기억·불변 스트리밍 스냅샷 테스트도 통과했다.

처음 수정 후 테스트에서 테스트 장면의 Pitch/Roll 표기를 혼동해 2층 assertion 하나가 남았다. 실제 Main 비교에서는 이미 정상 좌표였다. 테스트 장면의 X축 회전을 실제 Main과 동일한 Roll 180도로 수정하고 7개가 모두 통과했다. 구현 오류를 테스트 기대값 변경으로 숨긴 것이 아니며 전후 Main 실행 결과도 별도로 보존했다.

일반 Main 렌더링 PIE에서 화재 1/2/3을 별도 실행했다. 각 실행은 팔레트와 같은 클래스 NPC 4명을 두 층에 NavMesh/충돌을 확인해 임시 생성하고 25초 기록했다. 런타임 검사에서만 화재 지연을 0으로 두었고 저장된 메뉴 설정을 바꾸지 않았다. 세 실행 모두 연기 감지 및 Evacuating 전환을 확인했고, 최고 SelfSmoke는 각각 0.9961/0.9020/0.9255였다. 모든 기록에서 현재 판정 프레임은 화면 소수점 프레임의 내림과 일치했고 MissingData/InvalidMapping 눈 샘플은 없었다. 실제 마우스로 배치한 수동 검사나 전원 탈출 보장은 아니다. NullRHI 자동 테스트로 화면 표시를 검증했다고 주장하지 않는다.

## 남은 범위

이번 결과는 **현재 데이터의 소프트웨어 좌표 선택과 프레임 읽기 오류 수정**이다. 데이터 생성 스크립트가 없는 상태에서 정확한 FDS 좌표·물리 농도·섭씨 온도·원본 시간 간격을 새로 입증한 것은 아니다. 기존 공간 보정의 한 복셀 수준 오차, 1·2번 말단 VDB/BIN 불일치, 3번 BIN 998/VDB 997프레임 차이는 남는다. `bDatasetAlignmentConfirmed=false`를 유지하며 소화 반응의 물리적 근거로 승격하지 않는다.

실제 재생 중 UnsafePath 반복 거부가 여전히 관찰됐다. 다음 단계는 이 반복을 동일 조건으로 재현하고, 안전한 대안이 없는 상태와 탐색/기억 때문에 같은 위험 길을 재선택하는 상태를 분리하는 것이다. 문·계단 병목, 노출/기어가기, 60초 종료, 상호작용 제어는 그 뒤 순서로 진행한다.

증거와 재현 스크립트는 `Navigation1008Evidence/`에 있다. 스크립트의 프로젝트/출력 경로는 당시 환경 기록이므로 다른 컴퓨터에서 재사용할 때 경로를 조정해야 한다. 최종 실행 종료 로그의 RiderLink socket shutdown 메시지는 종료 시 기록이며, 자동 기록 JSON의 error 필드는 없고 정상 EndPlay/Editor shut down을 확인했다.
