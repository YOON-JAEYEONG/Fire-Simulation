## 원인과 수정

- 기존 배치 코드는 커서 광선 주변 500cm 범위에서 처음 발견한 NavMesh 높이를 사용했다. 실제 화면의 바닥과 관계없는 층/방을 선택할 수 있었고, 마지막 NavMesh 투영 실패도 성공으로 반환했다.
- 이제 커서 아래 첫 Visibility 충돌 표면을 검사하고 캐릭터가 걸을 수 있는 면인지 확인한다. NavMesh 투영은 수평 10cm, 높이 30cm 이내만 허용한다. 동일 위치에 캐릭터 캡슐이 들어갈 공간이 없으면 거부한다. 스폰 충돌 시 다른 곳으로 밀어내지 않고 생성하지 않는다.
- 드래그 이벤트의 화면 좌표를 Slate의 viewport pixel 좌표로 변환하여 배치한다. 미리보기도 같은 계산을 사용하며 유효하지 않으면 숨긴다.
- 방향 확인 중에는 해당 NPC의 Tick과 이동을 보류한다. 확인 시 이전 Tick/이동 모드를 복원하고, 취소 시 임시 NPC를 등록 해제하고 제거한다. 방향 UI 생성 실패도 취소 처리한다.
- 위젯 제거 시 미리보기/클릭 타이머, 임시 배치, 선택 UI를 정리한다. 실행 단계에서는 신규 배치를 거부한다.
- Main PlayerStart를 (2150,-3600,3600), pitch=-53, yaw=90으로 옮겨 건물을 가까이 보여준다. 층별 건물 형상은 변경하지 않았다.
- 팔레트 이름이 비어 있으면 NPC 배치로 대체하고 설명 툴팁을 붙였다. 기존 선택 항목의 텍스트 표시도 갱신한다.

- 첫 배치: (3050.830,-1137.024,440.150)에서 방향 설정 중 Tick=false 및 좌표 유지. 확인 후 Tick=true, 일상 이동 재개.
- 두 번째 배치: (1137.940,-1353.168,440.150), 방향 설정 중 Tick=false. 취소 후 전체 NPC 수가 2에서 1로 돌아왔다.
- 하늘로 드래그하면 Placement rejected 로그가 나오고 NPC 수는 증가하지 않았다.
- 두 성공 위치 모두 보이는 윗층 바닥이었다. 1층 배치/모든 벽·충돌 설정을 검증한 것은 아니다. 가려진 1층에 배치하려면 카메라에서 1층 바닥이 보이도록 해야 한다.

## 사용 순서와 제한

메뉴에서 Main을 연 뒤 게임 화면의 NPC 항목을 바닥으로 드래그 → 방향 확인 → 필요한 수만큼 반복 → HUD 시작.
콘텐츠 드로어에서 실행 중 NPC를 추가하는 것은 이 배치 흐름이 아니다. Main은 빈 상태로 시작한다. 실행 중 만든 NPC는 맵에 저장되지 않는다.
이번 작업은 배치/시작 화면 수정이다. BIN–VDB 좌표·시간 정합, 계단의 위험 경로 정지, 소화 메타데이터 부재는 이 수정으로 해결됐다고 주장하지 않는다.

마지막 화면 확인: 기존 팔레트 텍스트는 흰 배경 위 흰 글씨였으며 검은 글씨로 바꾼 뒤 표시됨을 확인했다. 기존 좁은 팔레트 슬롯에서는 긴 항목명이 잘릴 수 있다. 최종 에디터는 Main Play, NPC 0명 상태로 열어 두었다. 사용자가 게임 팔레트에서 배치할 수 있다.
