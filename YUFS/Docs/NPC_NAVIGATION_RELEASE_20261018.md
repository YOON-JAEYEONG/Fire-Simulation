도움 요청자는 움직이지 않도록 외부 내비게이션/이동 tick만 임시 보유했다. 도움 실행 결과가 실제로 요청을 해제한 뒤에만 이를 반환했다. 도움을 강제 완료하거나 사람을 삭제/순간 이동/충돌 해제하지 않았다. 이 조건은 ONNX 대신 기존 rule fallback을 선택하여 도움 계약을 검사했다. 잠금/고온은 작성된 문 플래그이며 연기에서 문 온도를 계산하는 새 모델이 아니다.

소화는 **명시적인 visual presentation** 시작을 요청한 동작/통행 검사다. 실제 FDS 발화 위치가 확인되지 않았으므로 자율 발화 감지·진압으로 보고하지 않는다. 도구 잔량은1로 유지되고 원본 화재를 바꾸지 않으며 종료 시 owner=None/프리뷰 비활성이다. 원본 FDS 메타데이터와 정합 확인 없이 소화를 허용하는 우회는 추가하지 않았다.

## 실행 경로와 배포 준비

예전 두 CMD는 공용 `C:\CodexWork\FireSimulationWorkspace`가 존재하면 이번 사본인지 확인하지 않고 재사용했다. 다른 사본이 열릴 가능성이 있어 **각 CMD가 위치한 폴더의 YUFS.uproject**만 직접 빌드/실행하도록 수정했다. 기존 공용 연결을 삭제하거나 다른 체크아웃을 바꾸지는 않았다.

`Tools/Test-YUFSCheckout.ps1`은 실제 브랜치/커밋, BIN3개 길이와SHA256, Main/메뉴/SVT6개 패키지 헤더를 검사한다. 빠른 실행은 로컬 DLL, 엔진 BuildId, 소스보다 오래된 DLL도 검사해 재빌드를 안내한다. 외부 Get-FileHash 자동 로딩에 의존하지 않고 .NET 스트림 해시를 사용해 Windows PowerShell에서 검사했다. 실행 파일은 UE 설치 위치 환경 변수 YUFS_ENGINE_ROOT를 지원한다. `--verify-only`는 검사만 실행한다.

다른 작업 디렉터리에서 두 CMD의 verify-only를 실행하여 올바른 프로젝트 경로를 확인했다. 현재 빌드 허용, 잘못된 브랜치/커밋 거부도 검사했다. 기존 C++ 파일과 DLL은11단계 검증 해시와 동일하다. 소스 프로젝트이므로 첫 클론과 C++ 갱신 후에는 현지 엔진으로 빌드해야 한다. README에 정확한 순서를 정리했다.

전체 **YUFS 자동 검사119개 성공/실패0개**(NPC115개 포함). 정상 Main3회·복합 Main4회는 각각 complete=true/error 없음, 프로세스0으로 완료했다. 기존 엔진 시작 Condition/default-BIN 및 RiderLink 종료/Chromium/USB 메시지는 남는다. 엔진 로그 전체가 무오류라는 뜻은 아니다.
