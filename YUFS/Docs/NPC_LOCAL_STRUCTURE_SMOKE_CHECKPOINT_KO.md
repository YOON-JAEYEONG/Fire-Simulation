# NPC 건물 탐색 및 근거리 연기 인지

이 문서는 `codex/fix-final-it-2f-doors`의 건물 인지·미닫이문 전환을 검증한 기록이다. 아래 단계별 대피 수치는 당시 작업본을 비교한 관찰값이며, 이후 이동 지도와 대피 정책 변경 전의 결과다.

- **건물 인지:** 보거나 직접 통과한 문, 시야 안의 통로와 실제 이동 지점만 기억한다. 숨은 출구는 지식에 추가하지 않는다. 알려진 출구와 안전한 경로가 우선이고, 실패한 탐색 목표는 잠시 피한다.
- **문 연동:** NavMesh 경로가 실제 문 개구부와 교차할 때 그 문을 대상으로 삼는다. 기존 문 열기·위험도·충돌·예약 로직을 우회하지 않는다.
- **근거리 연기:** 정면의 눈높이와 몸 높이 사이를 촘촘하게 검사한다. 뒤나 벽 너머, 다른 층의 연기 및 미로딩 데이터를 노출 근거로 쓰지 않는다. 기존 반응 임계값과 소지품 행동은 변경하지 않는다.
- **완료 조건:** 근거리 비정면 단일 연기 셀과 벽 차단, 문 교차/층 분리, 탐색과 기존 출구 정책의 회귀 테스트 및 건물 PIE 시각 확인.

## 건물 인지 검증

- [x] 기존 탐색·문 감지·연기 시야 코드를 확인했다.
- [x] 공간 기억과 문 교차로 탐색을 보완했다. 같은 위치에서 막힌 출구를 반복 요청하지 않고 이동 진척 이후 우선 재평가한다.
- [x] 근거리 연기 탐침과 벽 차단 회귀 테스트를 추가했다.
- [x] 최종 언리얼 빌드와 회귀 테스트 31개 통과. `LocalStructureFinalBuild.log`, `LocalStructureFinalTests.log`.
- [x] 화재 3번/1·2층 실제 플레이에서 공간 기억, 문 통과, 계단 이용, 근거리 연기 감지를 확인했다. 아래 결과와 남은 제한 참조.

확인용 맵은 UE 5.7의 `/Game/Maps/it관_찐최종/Main_level`이다. `-YUFSFireAwarenessAudit`로 NPC의 인지·탐색·회수 상태를 표시할 수 있다. 검증용 층별 10명 배치는 PIE에만 존재하며 맵에 저장하지 않았다.

## 실제 맵 1회차 결과와 후속 수정

화재 3번/20명/60초 실행(`LocalStructurePIE.log`): 문 기억 20명, 지역 탐색 9명, 대피 4명(1층 3명, 2층 1명), 행동 불능 0명. NPC #12는 경보 전인 1.77초에 앞쪽 연기를 감지했다. 그러나 열린 문짝과 동일한 경로의 반복 실패 때문에 이 결과를 해결로 간주하지 않는다.

후속 변경: 실제 충돌한 열린 문짝에서 문 폭/문 끝을 기준으로 짧은 우회 두 구간을 검사한다. 전체 출구 경로가 실패하면 기억한 문 앞까지 먼저 가고, 문을 연 뒤 양쪽 물리 바닥과 캡슐 충돌·화재 위험을 검사해 복도에 도달한다. 부분 경로를 완전한 대피 경로로 인정하지 않는다.

### 미닫이 변경

후속 회차도 총 대피 4명으로 동일했고 문짝 충돌은 37→41회였다. 사용자가 현재 건물 방 문을 미닫이로 요청했다. 기존 `MergeFinalDoor` 태그가 있는 문만 일괄 적용하고, 일반 여닫이 문은 유지한다. 문짝은 복도 쪽으로 돌지 않고 방 쪽 벽에 평행한 레일을 따라 이동한다. 충돌·잠금·과열·NPC 예약과 타임라인의 문 상태 복원은 유지한다. 다른 방으로 보이는 위치나 비상구 좌표는 바꾸지 않는다.

미닫이 적용 직후 검증:

- `SlidingFinalBuild.log`: 전체 프로젝트 DLL 링크 성공. 분리된 Unreal 검증의 `SlidingAutomation.log`: 미닫이 및 관련 회귀 32개 통과.
- `SlidingDoorMapAudit_room.json` / `SlidingDoorMapAudit_corridor.json`: 건물의 미닫이 30개 × 양방향 60건 통과. 닫힌 상태에서 막고, 회전 없이 옆으로 이동하고, 완전히 열리면 통로가 비는 것을 확인했다. 방 안쪽 레일이 막힌 2개 문은 벽 반대편에 얕게 설치했다.
- `Sliding_option3.json` / `SlidingNaturalTest.log`: 동일 화재 3번/20명/60초, 11명 비상구 도달(1층 10명, 2층 1명). 2층에서 내려온 NPC는 2명이며 그중 1명은 60초 안에 출구에 닿지 못했다. 문짝 충돌 로그는 비교 회차의 41건에서 2건으로 줄었다. #12는 경보 전 1.78초에 제자리 농도 0인 상태에서 앞쪽 연기를 감지했다. 60초에 남은 NPC나 2층 경로 병목까지 모두 해결됐다는 뜻은 아니다.
- `SlidingPreview.log`: 최종 건물 로드 및 `[SLIDING_HANDOFF]` 확인. `YUFS - Unreal Editor`에서 Play → 시작. 기본 카메라/OVERVIEW/PLAYER 자유시점은 그대로다. 20명은 임시 배치이며, 맵은 저장하지 않았다.

## 통합 변경 검증

- 커밋에 포함된 `Main_level.umap`에서 방 문 30개 모두 방 안쪽 사용 시험에 통과했다. 닫힌 상태에서는 캐릭터 크기의 캡슐을 막고, 문짝이 회전하지 않은 채 옆으로 이동한 뒤 개구부를 비웠다. 기존 터미널 출구 3개의 통로와 완전한 경로도 확인했다.
- 현재 이동 지도와 NPC 정책을 적용한 화재 3번 실제 맵 PIE에서 층별 10명 중 전체 20명이 약 40초에 탈출했다. NPC가 방 문 19개를 열었으며, 그중 가방을 가지러 방으로 되돌아간 NPC 3명도 탈출했다. 이 수치는 한 차례 재생의 관찰값이다.
