## 재현과 원인

타임라인에는 과거 대피·행동 불능 수가 이미 있었지만 HUD는 최종 실시간 집계를 읽었다. 새 회귀 검사 3개 중 수정 전 2개가 실패했다. 과거 1/2명 대피를 3/5명인 최종값으로 표시해 50% 대신 60%, 과거 시각 0:35 대신 최종 1:30이 나왔다. 빈 기록과 새 기록에도 최종값이 섞였다. 실시간 일시정지/완료 표시 검사는 수정 전에도 통과했다.

최종 실시간 getter를 바꾸면 게임 로직과 결과 집계가 과거 숫자를 읽게 된다. 따라서 표시용 `GetDisplayStats()`를 추가하고 HUD만 이 조회를 사용한다. 리뷰에서는 NPC 자세·화재에 실제 적용한 같은 기록 프레임을 읽고, 실시간/완료 상태에서는 기존 집계를 읽는다. HUD 조회마다 전체 NPC·소품 스냅샷을 복사하지 않는다.

프레임에 전체 참여 인원과 시뮬레이션 경과 시간도 저장했다. 나중에 추가/제거한 NPC가 과거 전체 인원을 바꾸지 않으며, 상단 시간에는 실제 화재 전 대기 시간이 포함된다. 슬라이더 시간은 기존처럼 화재 시작 후 시간이다. 기록이 없으면 인원은 `기록 없음`, 시간은 `--:--`, 대피율은 0으로 표시한다. 새 기록은 이전 리뷰 프레임 참조를 비운다. 기존 가장 가까운 프레임 선택 규칙은 유지한다.

상단의 `사망`은 실제로 행동 불능 집계이므로 `행동 불능`으로 고쳤다. 실제 사망/노출 로직이나 별도 최종 결과 창의 용어를 바꾼 것은 아니다. 기존 BP 함수 이름과 대피율 반환 단위 0~100은 유지하며 저장된 위젯/맵을 수정하지 않았다.

## 검증

UE5.7.4 Development Editor 빌드 성공. 전체 `YUFS.NPC` 검사 **115개 성공, 실패 0개**(기존 112개 + 새 3개). 과거/미래 왕복, 당시 전체 인원과 비율, 화재 전 시간을 포함한 시각, 빈 기록, 새 기록, 실시간 일시정지/완료/인원 0을 검사했다. 기존 실시간 대피·행동 불능 getter와 저장된 최종 결과가 과거 이동으로 변하지 않는지도 확인했다. 종료 코드 대신 실제 검사 결과 행을 집계했다.

렌더링된 실제 Main PIE에서는 팔레트 BP NPC를 사용했다. 이동 가능한 scale1 NPC 1명은 실제 출구 영역에 도달했고, 2층의 정지한 scale3 NPC 1명은 실제 BIN1 프레임480 노출로 행동 불능이 됐다. 시뮬레이션 12초에는 scale1 정지 대조 NPC 1명을 추가했다. 정지자는 외부 내비게이션 소유/이동 컴포넌트 정지로 위치만 고정했으며 노출·판단 tick은 유지했다. 행동 불능 상태를 강제로 넣지 않았다. 화재 전 대기2초/화재 후 기록46초는 검사 중 런타임 설정이다. 기본 노출값과 저장된 시나리오는 바꾸지 않았다.
