# NPC 경로 탐색 7단계 — 행동 불능 NPC의 표시와 종료 처리

2026-10-17. 프로젝트: `C:/Users/ACSLAB4/Documents/Codex/Fire-Navigation-1008/YUFS/YUFS.uproject`. 로컬 브랜치: `codex/merged-navigation-completion`. 기존 1~6단계를 보존했으며 이번 단계도 커밋/푸시하지 않았다.

## 확인한 문제와 수정

컨트롤러는 행동 불능 NPC를 집계하는 즉시 숨기고 Actor Tick을 껐다. 쓰러지는 애니메이션을 선택하는 NPC Tick보다 먼저 실행되면 이전 동작을 가진 채 사라졌다. Actor Tick만 꺼도 내비게이터와 CharacterMovement의 컴포넌트 Tick은 남아 있었다. 수정 전 노출 기반 회귀 검사 3개에서 숨김, 동작 누락, 남은 이동/탐색 시계와 재생 가시성 문제를 재현했다.

- 행동 불능 인원은 즉시 한 번만 집계하면서 NPC를 화면에 유지한다. 배우를 삭제하거나 애니메이션 종료까지 집계를 미루지 않는다.
- 종료 통지에서 일상/상호작용을 정리하고, 호환되는 기본 모션 담당 구성에는 비반복 `Dying` 클립을 즉시 선택한다. 이전 프리뷰가 남아도 종료 상태가 우선한다. 중복 통지가 같은 동작을 다시 시작하지 않는다.
- 판단 Tick, 경로 탐색 재시도와 CharacterMovement Tick을 멈춘다. 잔여 속도/이동 입력과 RVO를 해제하며 루트 모션으로 위치가 움직이지 않게 한다. 스켈레탈 시계는 유지해 동작 종료 후 마지막 자세를 표시한다.
- 외부 모션 담당 사용 설정은 존중한다. 호환되지 않는 애셋이나 외부 AnimBP에 기본 클립을 강제로 덮어쓰지 않는다.
- 종료 동작 표시는 마지막 정책 행동을 바꾸지 않는다. 따라서 종료 학습 기록에 실제 직전 행동을 보존한다.
- 일시정지는 쓰러지는 애니메이션도 멈추고, 재개 시 판단/이동은 다시 켜지지 않는다.
- 기록 재생은 해당 시점의 가시성과 실제 클립/커서를 복원한다. 실제 Main 재생 검사 중, 가시성만으로 충돌을 켜는 기존 복원 코드가 행동 불능 배우를 다시 충돌체로 만드는 것을 추가로 발견했다. 재생에서도 행동 불능/대피 완료 배우는 기존 종료 충돌 해제 정책을 유지하도록 수정했다. 이전의 건강한 시점으로 되감으면 정상 충돌을 복원한다.

`Dying`은 현재 저장소의 애니메이션 이름이며, 행동 불능을 의학적 사망으로 확정한다는 뜻이 아니다. 기존 노출 누적률/임계값, 화재 데이터, 성향, 맵/블루프린트/애니메이션 애셋은 변경하지 않았다.

## 검증

UE 5.7.4 Development Editor 빌드 성공. 전체 `YUFS.NPC` 자동 검사 **96개 성공, 실패 0개**. 이전 93개에 다음 3개를 추가했다.

- `Incapacitation.VisibleStationaryAndCountedOnce`: 실제 누적 노출로 상태를 전환하고, NPC Tick 전 집계에서도 보이는 비반복 종료 동작이 선택되는지, 이동/탐색 정지, 잔여 입력/RVO 제거, 중복 집계/동작 재시작 방지와 마지막 자세 유지를 검사한다.
- `Incapacitation.PauseAndHistoricalPose`: 일시정지/재개, 건강한 기록과 행동 불능 기록 사이의 클립/커서/가시성/충돌 복원, 기록 인원과 현재 결과 유지, 재생 중 독립적인 동작 진행 방지를 검사한다.
- `Incapacitation.PreservesExternalMotionDriver`: 외부 모션 소유권과 애니메이션 구성을 덮어쓰지 않으면서 위치 이동/탐색을 멈추는지 검사한다.

일반 Main의 팔레트 Blueprint 클래스 NPC 두 명을 렌더링 PIE에서 임시 생성했다. 실제 BIN 1번의 480프레임을 고정하고, 누적 노출을 비교하기 위해 두 NPC를 정지시켰다. 노출 배율은 기존 기본값 3과 비교값 1이다. 행동 상태를 강제로 설정하거나 맵에 저장하지 않았다. 검사에서만 화재 지연 0초/기록 54초를 사용했다. 일반 시나리오의 기본 30초 지연/60초 기록은 그대로다.

- 배율 3은 약 38초에 행동 불능으로 집계되며 보이는 상태에서 `Dying`을 시작했다. 클립 길이는 약 5.767초이고, 커서가 끝까지 진행한 뒤 같은 위치에서 유지됐다. 배율 1 비교 NPC는 기록 종료 시점까지 행동 불능으로 집계되지 않았다.
- 쓰러지는 도중 두 벽시계 초 동안 일시정지하여 시뮬레이션 시간, 화재 프레임, 위치와 클립 커서가 변하지 않음을 확인했다. 재개 후 동작은 진행하고 판단/이동은 정지 상태를 유지했다.
- 자동 관찰 모드 전환 후 기어가는 시점, 쓰러지는 중간, 처음, 쓰러진 후를 이동하며 선택된 저장 프레임과 클립/커서/가시성/충돌이 일치하는지 확인했다. 관찰 일시정지 중 커서가 독립적으로 진행하지 않고, 이동해도 현재 결과를 중복 집계하지 않는다.
- 실제 Stop으로 Main을 다시 불러온 뒤 행동 불능 인원 0, 새 NPC 노출 0, 정상 가시성/충돌/이동 Tick을 확인했다.

최종 실행 자료와 소스/DLL 해시는 `NavigationStep7Evidence`에 보관한다. 자동 렌더링 실행이며 사람이 화면에서 쓰러지는 동작의 미관을 확인한 결과는 아니다. 고정 데이터/정지 NPC는 누적 노출과 생명주기 검사 조건이며 일반 대피의 생존 비율을 의미하지 않는다.

최종 전체 검사와 최종 Main 진단 프로세스는 모두 반환 코드 0으로 종료했고, 진단 에디터 종료를 확인했다. 기존 시작/종료 경고는 남아 있으므로 전체 로그가 무오류라는 뜻은 아니다.

## 진단 조건과 남은 한계

- 첫 단위 검사의 마지막 자세 검사는 별도 렌더러가 없는 월드에서 애니메이션의 지연 평가를 완료하지 않아 실패했다. 테스트 하네스에서 엔진 평가를 완료하고 끝점을 처리하는 후속 업데이트를 호출하도록 보완했다. 실제 Main에서도 별도로 클립 진행/끝점 유지를 검증했다. 이 하네스 문제를 게임의 애니메이션 고장으로 제시하지 않는다.
- 첫 Main 진단은 Pause/Resume 후 화재가 정상 재개되어 고정 480프레임 조건을 벗어났다. 진단 스크립트에서만 재개 직후 480프레임을 다시 고정했다. 정상 화재 재개 동작은 바꾸지 않았다.
- 충돌 복원 수정 전 실행 자료는 별도 이름으로 남긴다. 당시 기록 재생 충돌은 `true`였으므로, 이를 최종 충돌 검증 근거로 쓰지 않는다.
- 종료 NPC의 충돌을 해제하는 기존 정책을 유지했다. 쓰러진 몸을 실제 바닥 장애물로 만들거나 다른 NPC가 운반/넘어가는 물리 모델은 이번 범위가 아니다. 기어가는 자세에서 종료 클립으로 바뀌는 연출의 자연스러움, 외부 AnimBP 자체의 행동 불능 전환은 모션 구성과 함께 추가 확인이 필요하다.
- 일부 HUD/디버그 표시는 여전히 기록 시점의 수치 대신 현재 최종 결과를 사용한다. 이번 단계는 기록된 배우/프레임 데이터의 정합을 검사했으며 HUD 전체를 역사 시점 표시로 바꾼 것이 아니다.
- 이 실행은 화재 데이터 1종의 고정 프레임을 이용한다. 3종의 정상 전개, 고밀도 반대 방향 군중과 상호작용 스트레스 검증은 남아 있다. 원본 물리 단위/전체 시퀀스 정합 미확인과 `bDatasetAlignmentConfirmed=false`도 유지한다.
- 로그에는 기존 시작 단계 `Condition failed`, 선택 옵션 적용 전 기본 BIN 경로 부재, RiderLink 종료 메시지가 남는다. 최종 테스트의 성공과 엔진 전체 로그가 깨끗하다는 주장은 다르다.

작업은 로컬에만 있으므로 지금 GitHub를 새로 클론하면 이번 1~7단계 변경이 자동으로 포함되지 않는다. 배포 전에는 해당 작업 브랜치의 커밋/게시와 새 클론 검증을 별도로 완료해야 한다.
