# 일반 Play의 소화 접근 및 출구 정체 보완

대상: `JJW_CYW_ZION`, 기준 커밋 `22d1a08`. Windows UE 5.7.4에서 검증했다.

## 실행

`YUFS.uproject`를 열고 `Prototype`에서 Play 후 화재 시작을 누른다.
프리뷰 Python이나 `-YUFSBuildingInteractions` 플래그가 필요하지 않다.
BIN은 `Content/Fires/Scenario_01/smoke_data.bin`에 있어야 한다.

## 변경

- 소화기 위치에서 목표까지 직선 시야가 나와야 한다는 시작 제한 대신, 같은 층의 도달 가능한 분사 위치를 NavMesh와 충돌·시야로 검사한다. 기존 NPC가 소화기를 집고 그 위치까지 실제 이동한 뒤 준비·분사를 수행한다. 도착 시 시야를 다시 검사한다.
- 대피 완료 NPC의 CharacterMovement 이동과 RVO 참여를 해제한다. 화면과 액터 충돌만 꺼진 NPC가 출구의 보이지 않는 회피 대상으로 남는 문제를 방지한다. 타임라인에서 라이브로 복귀할 때 회피를 복원한다.
- 서로 양보하는 순환이 생기면 해당 순환에서 하나의 NPC에 우선권을 준다. 일반 앞뒤 대기열과 물리 충돌 검사는 유지한다.

## 검증

- Development Editor 빌드 성공, NPC 자동화 테스트 66개 성공/실패 0.
- 추가 회귀 검사: 3인 양보 순환의 단일 우선권, 대피 완료 후 RVO·이동 종료 및 라이브 복귀, 소화기 획득 후 분사 지점에 접근하기 전 분사 금지.
- 같은 Prototype의 일반 Play/Start 흐름을 100초간 비교했다. 수정 전 9/20 대피, 수정 후 20/20 대피를 로그에서 확인했다. 수정 후 기존 NPC C_4의 분사 시작, 8초 분사 완료, 대피 복귀를 확인했다.
- 검사는 NullRHI에서 수행했다. 테스트 스크립트는 Play와 Start 및 상태 기록만 수행하며 NPC 배치, 목표, 위험 값, 분사 선택을 강제하지 않는다. 렌더링 화면 검증 또는 모든 배치·프레임률에서의 전원 대피 보장은 아니다.

## 범위

현재 일반 실행의 소화 동작은 `DefaultGame.ini`의 명시적 `YUFSAuthoredSuppressionScenario`에 속한다. 검증된 FDS 발화 정보나 실측 행동 확률의 결과로 취급하지 않는다. BIN/SVT 좌표 대응을 임의로 승인하지 않으며, 분사로 녹화된 화재·연기를 감소시키거나 학습 기록에 진압 성공을 기록하지 않는다. 실제 화재 기반 진압은 별도의 발화 메타데이터와 데이터 정합 확인이 필요하다.
