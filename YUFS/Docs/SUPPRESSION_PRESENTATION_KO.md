# 소화기 표시와 분사 동작 확인

## 확인한 원인

2026-09-15 Mac 실제 실행 로그에서 `-YUFSBuildingInteractions` 전달, 소화기 1개 생성, NPC의 해당 소화기 관측을 확인했다. 생성 자체가 실패한 것은 아니었다. 기존 배치 코드는 NPC가 모여 있으면 650cm 간격 제한 때문에 한 곳에만 소화기를 두었다.

같은 로그에 `MissingFdsIgnitionMetadata`와 `FDS-source=None`이 있었다. 일반 소화 실행기는 확인된 발화점, 위험 데이터 정합, 개인 관측, 퇴로 조건을 요구하므로 이 맵에서 분사에 진입하지 않았다. 소화기 액터, 배치 코드, 소화 실행기의 수정 전 내용은 `zion-fs@086fe2b`와 동일했다. 통합 충돌에서 해당 기능이 삭제된 것은 아니다.

## 사용 방법

### 일반 Play 연결 (최신 소스, 재빌드 필요)

1. 최신 C++ 모듈을 빌드한 후 `YUFS.uproject`를 열고 `Prototype` 맵을 연다.
2. Play를 누르면 약 4초 후 소화기를 기본 배치한다. 맵에 이미 소화기가 있으면 기본 목표 수량 4개에 포함해 계산한다. NavMesh나 NPC가 준비되지 않으면 목표 수량보다 적을 수 있다.
3. 화면의 시뮬레이션 시작 버튼을 누른다. 화재 카운트다운 동안에는 소화 동작을 시작하지 않는다.
4. 화재 활성 단계에서 지정 지점과 소화기가 보이고, 소화기에 도달 가능한 기존 NPC 한 명이 약 8초간 분사 동작을 시도한다. 사용자 카메라는 바꾸지 않는다. 위험 감지·기어가기·이동 불능 상태에서는 중단하고 기존 판단을 계속한다.
5. 이번 연결은 사용자가 요청한 **지정 좌표 대상 시나리오**이다. 실제 발화점 감지나 행동 확률 검증 결과가 아니다. 적절한 NPC나 접근 경로가 없으면 강제로 이동시키지 않으며, 출력 로그에 이유를 남긴다.

설정은 `Config/DefaultGame.ini`에 있다.

- `[/Script/YUFS.YUFSGameInstance] bEnableBuildingInteractions=True`: 별도 실행 옵션 없이 환경 소화기 배치.
- `MinimumExtinguisherCount=4`: 기존 소화기를 포함한 배치 목표 수량.
- `[/Script/YUFS.YUFSAuthoredSuppressionScenario] bEnabled=True`: 지정 지점 시나리오 활성화. 실제 행동 통계나 FDS 검증 실행에서는 `False`로 끈다. 실행 옵션 `-YUFSDisableAuthoredSuppression`으로도 끌 수 있다.
- `MapName=Prototype`: 다른 맵에서는 지정 좌표 시나리오를 실행하지 않는다.
- `TargetWorldLocation=(X=-265.66,Y=1156.58,Z=423.00)`: 마지막 시연에 사용한 월드 좌표(cm). 실제 FDS 발화점으로 등록하지 않는다.
- `SprayDurationSeconds=8.0`: 분사 표시 시간.

시나리오가 NPC 이동과 소요 시간에 영향을 주므로 활성 상태의 대피 결과를 자연 행동 확률 검증에 사용하지 않는다. 기존 타임라인은 별도로 유지하지만, 소화기 도구의 상세 동작 재생은 이번 변경의 검증 범위가 아니다.

### 별도 애니메이션 확인 런처

1. 기존 Unreal Editor를 종료한다. 이미 열린 에디터는 새 C++ 빌드를 사용하지 않을 수 있다.
2. 프로젝트 루트의 `Preview-Suppression-Mac.command`를 더블클릭한다. Windows용은 `Preview-Suppression-Windows.cmd`이다.
3. 맵이 열리고 Play가 자동 시작된다. 소화기 배치를 기다린 뒤 기존 NPC 한 명을 대상으로 카메라를 맞춘다.
4. 해당 NPC가 소화기로 이동하고 집어 든 뒤, 약 20초간 분사 표시를 한다. 끝나면 원래 NPC 판단으로 돌아간다. Esc로 Play를 종료한다.

이 실행 파일은 **애니메이션 확인용**이다. 일반 `.uproject` 실행과 구분한다. 별도 NPC나 불을 만들지 않고 기존 캐릭터와 소화기 에셋을 사용한다. 화면을 확인하기 위해 시연 카메라만 일시 생성하며 맵을 저장하지 않는다.

## 변경 사항

- 환경 소화기를 NPC 주변 여러 방향의 NavMesh 위에 분산 배치한다. 벽 너머와 다른 층 후보는 거르고, 각 액터의 위치를 로그에 출력한다. 편집기 Outliner 이름은 `Extinguisher_01` 형식이다.
- 명시적 `StartVisualPresentation` API를 추가했다. 일반 소화 행동의 데이터 조건을 몰래 완화하지 않고 분리된 동작 시연으로 실행한다.
- 기존 손동작 바인딩과 소화기 노즐의 분사 메시를 재사용한다. 새 전용 모션 캡처 애니메이션을 추가한 것은 아니다.
- 시연 목표는 화면 표현을 위한 지정 지점이다. 실제 FDS 발화점으로 기록하거나 위험 관측으로 사용하지 않는다.
- 시연은 화재 강도, 소화 성공, NPC 대피 성공을 변경하지 않는다. 시연 구간의 학습 전환과 타임라인 기록은 제외한다.
- 종료·취소·타임라인 전환에서 분사와 도구 예약을 해제한다. 기존 위험 기반 소화 실행 조건은 유지한다.

## 검증

**아래 69개 테스트 및 화면 캡처는 일반 Play 연결 이전 빌드의 결과다.** 일반 Play 연결, 위험 중단, 도구 변환 복구 테스트를 추가했으나 Xcode 27.0 호환 문제 때문에 최신 소스의 컴파일과 추가 테스트, 일반 Play 화면 검증은 아직 완료하지 못했다. 현재 남아 있는 오전 실행 파일을 열어도 최신 일반 Play 동작은 반영되지 않는다.

- 2026-09-15 오전 Mac UE 5.7 Editor Development 빌드 성공.
- 같은 날 오후 기존 빌드로 전체 자동 테스트를 재실행해 69개 성공(경고 포함 성공 4개), 실패 0개를 확인했다. 분사 메시 표시, 시연 종료, 기존 행동 상태 보존, 타임라인 취소 테스트 포함.
- 오후 재빌드는 현재 설치된 Xcode 27.0이 이 UE 5.7의 허용 범위(15.2~26.9)를 벗어나 시작 단계에서 차단됐다. 소스 컴파일 오류와 구분해야 한다. 새 C++ 수정 후 재빌드하려면 호환되는 Xcode 환경이 필요하다.
- 검증 기록: 프로젝트 옆 `../NPC_Suppression_2026-09-15/` 폴더. 자동 테스트 통과만으로 실제 화면 검증을 대신하지 않는다.
- Metal 도구 설치 후 오후 실제 렌더링에서 소화기 4개 생성, 기존 NPC의 소화기 들기와 분사 자세를 확인했다. 캡처는 위 폴더의 `yufs-suppression-spray.png`이다. 이전 벽 가림 문제는 이번 캡처에서 재현되지 않았다.
- 현재 분사 표시는 기존 원통 메시이며 화면에서 어두운 막대처럼 보인다. 자연스러운 소화 분말 파티클이나 전용 소화 모션까지 완성된 상태는 아니다.
- 화면 검증 실행은 캡처 후 종료 시 RiderLink 소켓 오류와 종료 코드 1을 남겼다. 화면 확인 성공과 에디터의 정상 종료 검증은 구분한다.
- Windows 런처는 경로 형식을 제공했지만 이 Mac에서 Windows 실행을 검증한 것은 아니다.
