# 건물 안 상호작용 시각 확인

## 실행

루트 `Launch-InteractionPreview.ps1`을 실행한다. 기존 Prototype 건물과 기존 대피 NPC를 사용한다.
실행 직후에는 자동 시연하지 않고 기다린다. **기존 왼쪽 위 `시작` 버튼**을 누르면
문 열기·통과 → 문 밖 가까이에 있는 NPC 돕기 → **두 NPC 모두 대피**를 연속으로 실행한다.
NPC 초기 배치는 시작 때 한 번뿐이며, 행동 단계가 바뀌어도 위치를 다시 설정하지 않는다.
열린 문은 그대로 남아 다른 NPC도 통과할 수 있고, 중지에 따른 레벨 초기화 때만 제거된다.
**상단 시연 패널과 자동 포커스는 없다.** 기존 플레이어 자유시점으로 직접 이동해 관찰한다.
시연 코드는 카메라 액터를 생성하거나 ViewTarget·마우스 커서·입력 모드를 변경하지 않는다.
시작 전 준비에는 약 4초가 걸리며, 그 전에 시작을 눌러도 요청을 한 번 예약하여 준비 후 실행한다.
개별 시연 버튼은 제거했다. 다시 보려면 **중지 → 시작**을 사용한다. 실패 시 다음 단계로 넘어가지 않는다.
**일시정지**는 시연 진행·문 회전을 멈추고, **시작**은 이어서 재생한다.
**정지**는 레벨을 다시 불러오고 준비 상태로 돌아온다. 그 후 **시작**으로 전체 순서를 다시 확인한다.
시연 전용 플래그는 `-YUFSBuildingInteractions -YUFSInteractionPreview`다.

현재 Prototype의 기본 플레이어는 자유 이동 `DefaultPawn`이다. WASD 이동, 마우스 회전,
E/Space 상승, Q/C/Ctrl 하강을 사용한다. PIE에서 버튼 클릭용 마우스가 필요하면 **Shift+F1**로
해제하고, 뷰포트를 클릭하여 다시 이동한다. 수동 카메라 버튼으로 시점을 바꿨다면 기존 **PLAYER**로 복귀한다.
중지 시 레벨 재로드로 플레이어 시작 위치도 초기화되며, NPC 행동 단계 전환은 플레이어 시점을 바꾸지 않는다.

### 시작 버튼 연결

- `SimulationUIWidget`의 시작/일시정지/정지/초기화를 실제 `YUFSSimulationController` API에 연결했다.
  `YUFSSimHUD`의 기존 버튼도 같은 중앙 시작 API를 사용한다.
- `GameInstance`는 오브젝트 준비만 하고, 미리보기 모드에서는 임의로 시뮬레이션을 시작하지 않는다.
  컨트롤러가 레벨마다 준비 함수를 호출하므로 Stop/Reset 이후에도 준비가 누락되지 않는다.
- NPC 분산이 끝나기 전에 실행 단계로 넘어가지 않도록 준비 상태를 확인한다.
  시작 연타는 시연/문을 추가 생성하거나 시간을 초기화하지 않는다.
- 일반 실행(시연 플래그 없음)의 행동 확률을 강제 변경하는 기능이 아니다.

## 화면에서 확인할 것

1. 문 열기: NPC가 파란 문에 접근 → 문 방향으로 몸을 돌려 손 사용 → 문짝 회전 → 열린 문 통과.
2. NPC 돕기: 도움을 요청한 보행 가능자에게 접근 → 두 사람이 서로 바라보며 대화 → 안내받은 사람이 기존 대피 판단을 재개.
3. 도움 완료 후 도움을 준 사람과 받은 사람 모두 기존 대피 AI로 돌아간다. 방 앞에서 사라지거나 대기 명령에 고정하지 않는다.
4. 완료 여부는 실제 문 열림/상호작용 피드백을 읽어 로그에 기록한다. 정해진 시간이 지났다고 성공으로 처리하지 않는다.
   도움 완료와 탈출 완료는 별개다. 실제 출구 도달은 기존 SimulationController가 판정하고, 그때 기존 방식대로 NPC가 숨겨진다.

## 배치와 범위

- 방 출입구는 실제 재생 월드의 벽 충돌 검사를 통해 확인했다. 2층 남측 벽 Y≈79.7cm에
  X=-450~-400cm가 열려 있는 구간을 사용하며 문 경첩은 `(-480,90,351)`, yaw=-90도다.
- 기존 2층 NPC 2명을 골라 시연 시작 때만 NavMesh 검사를 거친 위치에 초기 배치한다.
  시연 단계 전환에서 순간이동하거나 별도 전용 NPC를 생성하지 않는다.
- 도움 대상의 초기 바닥 위치는 문 밖 복도 `(-240,230,351)`이며, 문을 연 NPC는 자기 위치에서 걸어서 접근한다.
- 도움 성공/실패·시간 초과 이후에는 두 NPC 모두 시연 제어에서 해제한다. 각자의 현재 위치에서
  출구와 완전한 경로를 확인해 CommitEvac 또는 Shelter 의도로 넘긴다. 경로가 없는데 대피 성공으로 표시하지 않는다.
- 문은 해당 시연에서만 생성되는 런타임 액터다. 원본 건물 `.umap`은 저장/변경하지 않았다.
- 별도 불을 만들지 않는다. 다른 기존 주민의 대피·소화 기능은 유지한다.
- 선택된 두 NPC의 판단 입력만 시연용으로 지정하고, 기존 발견·예약·경로·실행기를 사용한다.
  따라서 이 화면은 **행동 기능 시연이지 자연 발생 비율 검증이 아니다.** 일반 실행에는 이 지정을 적용하지 않는다.
- 120초 후 타임라인 관찰 모드로 넘어가 버튼이 작동하지 않던 것을 막기 위해 시연 모드에서만
  타임라인 기록을 끄고 최대 시간을 1시간으로 설정했다. 일반 실행 설정은 유지한다.

## 보완된 기능

- 문짝만 경첩을 중심으로 회전하며 문 액터의 기준 위치는 고정한다. 파란 문짝, 문틀, 양면 손잡이와 경첩을 추가했다.
- 문은 첫 조작자의 반대 방향으로 열리며 완전히 열릴 때까지 통로의 Pawn 충돌을 유지한다.
- 도움을 받는 NPC는 실제 접촉 안내 중에만 멈추고 상대를 바라본다. 일반 모드의 위험 인지·일시정지는 계속 갱신한다.
- 목표가 같은 지시의 metadata revision 변경은 진행 중인 예약을 취소하지 않는다.
- 재생 전 피드백 세대와 현재 요청 revision을 확인하여 이전 도움 성공 결과를 재사용하지 않는다.
- 경로 목적지의 바닥 높이 차이 때문에 매 프레임 새 경로를 요청하던 시연 문제를 XY 비교로 수정했다.

## 한계

문 손 사용은 기존 호환 애니메이션을 재사용한 임시 표현으로 정밀 손잡이 IK가 아니다.
도움은 대피 안내이며 부상자 운반·치료·끌기는 구현하지 않았다.
실제 연기/열 원본 데이터 누락은 별도로 남아 있어 안전성 검증 용도가 아니다.
문 배치를 일반 시나리오에 영구 적용하거나 잠긴 문 우회·방화문 자동 닫기를 구현한 것은 아니다.
