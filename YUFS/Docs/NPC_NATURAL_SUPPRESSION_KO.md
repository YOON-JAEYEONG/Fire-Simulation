# 기존 대피 NPC의 소화기 사용

> 최신 구현은 [지정 방 화재 효과 및 확률 소화](LOCAL_FIRE_EFFECT_AND_RATIO_KO.md)를 따른다.
> 아래 내용은 이전 실험 기록이며 현재 확률·시간 제한·연결 상태와 다를 수 있다.

> 최신 연결 상태와 원본 데이터 누락 근거는 [기존 화재 연결 문서](NPC_EXISTING_FIRE_INTEGRATION_KO.md)를 참고한다.
> 아래 내용은 과거 임시 화재 검증 기록을 포함하며 현재 실행 결과로 해석하면 안 된다.

> 현재 상태 (2026-09-08): 아래 소규모 화재 객체 기반 검증은 이전 실행 기록이다.
> 사용자 요청에 따라 건물 실행의 추가 화재 생성과 구형 전용 시연을 차단했다.
> 현재 실행은 소화기만 추가하며, 기존 `YUFSHeterogeneousVolume`을 변경하거나 대체하지 않는다.
> 기존 화재의 실제 발화 지점/유효한 진압 결과를 NPC에 전달하는 연결은 아직 미구현이다.
> 따라서 현재 실행에서 이전처럼 임시 불에 소화하는 장면이 나오는 것을 기대하면 안 된다.

## 동작

건물의 기존 `AYUFSEvacuationNPC`에 `UYUFSNpcSuppressionComponent`가 붙는다.
NPC를 교체하거나 새 소화 전용 NPC를 생성하지 않는다. 기존 mesh, skeleton,
캐릭터 이동과 인지 상태를 유지한 채 행동을 전환한다.

1. 시뮬레이션 활성 상태에서 약 0.5초마다 가까운 소화기와 소규모 화재를 시야 검사한다.
   한 번 본 위치는 최대 15초 기억한다. 실제 획득·분사는 그 순간의 거리와 시야를 다시 검사한다.
2. 발견한 객체와 기존 출구 시스템의 퇴로 정보가 판단기로 전달된다.
3. 훈련 수준 0.55 이상, 인지 위험 0.65 미만, 도달 가능한 퇴로, 유효한 소화기와 화재가
   있어야 후보가 된다. 공식 대피 안내·행동불능·기어가기 상태는 우선한다.
4. 이미 대피를 결심한 NPC도 새로운 화재/소화기 조합을 처음 만났을 때 소화를 선택할 수 있다.
5. 선택한 NPC가 소화기를 예약하고 기존 smoke-aware navigator로 접근한다. 다른 NPC는
   같은 소화기를 동시에 획득할 수 없다. 순간이동은 사용하지 않는다.
6. 획득 후 약 2.3m 이격 지점으로 이동한다. 거리·높이·시야를 다시 검사하고 준비시간 후 사용한다.
7. 약제를 소모해 연결된 소규모 화재의 강도를 줄인다. 소진·35초 제한·목표 상실·퇴로 상실·위험 증가 시
   중단하고 기존 판단으로 돌아간다. 소화 완료를 시간 경과만으로 판정하지 않는다.

## 선택 확률

대피 중 새 조합에 대한 기본값은 다음과 같다.

`P = clamp(0.25 × (0.5 + 훈련) × (0.5 + 도움 성향) × (1 − 인지 위험), 0, 1)`

0.25는 `YUFSBehaviorPolicy.EvacuatingSuppressionProbability`의 조정 가능한 설계값이다.
실증 연구에서 얻은 행동 비율이 아니며, 전체 NPC의 25%가 소화한다는 뜻도 아니다.
한 조합을 거절한 NPC에게 매 틱 다시 추첨하지 않는다. 획득 중·사용 중에는 선택을 유지한다.
안전 조건이 사라지면 선택을 유지하지 않는다.

## 건물에서 확인

`Launch-NaturalNpcInteractions.ps1`을 실행한다. 기존 `Prototype` 건물과 기존 주민들을
사용하고 환경 객체만 최대 네 쌍 추가한다. 애니메이션 갤러리와 기존 소화 전용 시연은 실행하지 않는다.
검증 시나리오는 안정 NPC ID가 3의 배수인 주민의 훈련 수준을 0.85로 설정한다.
이는 훈련자/비훈련자가 함께 있는 검증 조건이며, 소화 선택 자체를 강제하지 않는다.
일반 실행에서는 NPC의 `HumanCognitionComp.Traits.FireTraining` 또는 PolicyAsset에서
팀이 훈련 수준을 지정한다. 기존 기본값은 0이므로 훈련자를 설정하지 않으면 선택하지 않는다.

로그 `[NPCSuppression] SAME actor ... started suppression`과
`SAME actor ... resumes decision`의 이름을 비교하면 같은 개체가 행동을 전환했는지 확인할 수 있다.

## 팀 연결과 현재 범위

- 경로: 기존 navigator와 캐릭터 steering을 사용한다. 외부 navigation driver가 활성화되면
  외부 담당자가 directive를 받아 상호작용 접근 지점을 처리해야 한다.
- 모션: 외형 교체 없이 같은 스켈레톤의 걷기/양손 동작을 사용한다. 현재 양손 동작은
  기존 태블릿 동작을 재사용한 임시 표현이다. 전용 소화 애니메이션과 양손 IK는 아직 필요하다.
- 상호작용: 이 컴포넌트가 소화기 탐색·예약·사용·해제를 담당한다. 외부 interaction adapter를
  병합할 때는 `bEnabled=false`로 꺼서 실행 소유자가 중복되지 않게 한다.
- 화재: `AYUFSSuppressibleFireSource`의 강도만 감소한다. 기존 사전 계산 smoke/화재 데이터는
  이 값과 연동되지 않으므로 건물 전체 연기까지 실제로 줄어드는 구현은 아니다.
- 퇴로: 기존 LevelDataManager 출구 데이터와 NavMesh를 사용한다. 개인별 출구 기억 모델의
  완성이나 실제 안전성 검증을 의미하지 않는다.
- 이 기능은 라이브 시뮬레이션 실행 대상이다. 소화기 소유권·잔량·불 강도의 타임라인 재생은
  별도 기록 필드를 추가해야 한다.

## 실제 건물 실행 검증

2026-09-07 실행 로그: `Logs/NaturalNpcBuilding5.log` (아래 시간은 로그의 UTC).
검증용 환경 객체 네 쌍만 생성했고 추가 NPC는 0명이었다.
기존 `BP_YUFSRLEvacuationNPC_C_0`에서 다음 연속 동작을 확인했다.

| 시간 | 같은 NPC에서 발생한 동작 |
| --- | --- |
| 14:57:01 | 소화 시도 선택 |
| 14:57:02 | 소화기 0 직접 획득 |
| 14:57:04 | 화재 0에 분사 시작 |
| 14:57:09 | `FireExtinguished`로 진압 완료 |
| 14:57:15 | 다른 화재 2에 추가 분사 |
| 14:57:18 | 약제 소진으로 중단 (`SuppressionTimedOutOrEmpty`) |
| 14:57:42 | 기존 출구 시스템에서 `evacuated successfully` 확인 |

이는 기능 실행 검증이며 전용 소화 자세·손잡이 정렬·분말 효과의 시각적 완성도 검증은 아니다.
완료 후 새 화재/소화기 조합을 발견하면 다시 선택할 수 있으므로, 한 번 진압한 모든 NPC가
즉시 출구로만 가도록 강제한 모델은 아니다.

상호작용 접근에는 일반 대피보다 작은 20cm 도착 허용 오차를 적용한다.
획득 직후 이동 목표를 고정된 소화 위치로 전환하고, 자신이 소유한 도구는 화재 시야 검사에서 제외한다.
현재 배포된 로컬 데이터에는 `Scenario_01/smoke_data.bin`이 없어 로딩 오류가 기록된다.
따라서 이번 결과는 소규모 화재 객체와 건물 이동의 검증이며 실제 연기 변화에 따른 통합 검증은 아니다.

빌드: UE 5.7 `YUFSEditor Win64 Development` 성공.
회귀 테스트: `YUFS.NPC` 9개 모두 성공 (`Logs/NaturalNpcTestsVerified.log`).
여기에는 대피 중 소화 선택, 획득 후 선택 유지, 반복 추첨 방지, 퇴로 상실 시 대피,
비훈련자·공식 안내 조건, 타이머만으로 소화 완료 처리하지 않는 검사가 포함된다.
