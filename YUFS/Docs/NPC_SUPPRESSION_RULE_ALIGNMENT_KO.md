# NPC 소화 시도·문 통과 규칙 정합 인계

> 보관 기록: 이 문서는 2026-09-10 체크포인트의 설계·검증을 설명한다. 현재 실행 규칙은 [JJW 우선 병합 안내](JJW_PRIORITY_MERGE_KO.md)를 따른다. 현재는 JJW 전체 병합으로 8,192셀 개인 지각, JJW 상태머신·국소 이동을 사용하며, 아래의 256개 표본·옛 의도 투영·소화 후 Shelter 전환·35개 테스트 수는 현재 구현 설명이 아니다. 즉시 연기 위험 기준도 JJW 설정값(기본 자기 위치 연기 > 0.30)을 따른다.

## 1. 이번 변경의 결론

기존 건물의 같은 대피 NPC가 소화기를 발견하면 소화를 **시도**하고, 자신이 인지한 위험이 커지면 시도를 중단하고 대피 판단으로 돌아가게 한다. 소화 행동은 FDS의 연기·열·연소 결과를 바꾸지 않는다.

- 유지: 소화기 발견·예약·집기·운반·조준·분사 표현, 기존 NPC와 이동 계층, 원본 FDS/SVT 재생.
- 제거: 추가로 만들었던 국소 화염/연기 플레인·주황색 조명, 분사량에 따른 가상 화재 강도 감소, 일정 시간 후 진압 성공 처리.
- 변경: 발화점은 검토한 FDS 메타데이터에서만 제공한다. NPC 위험 판단과 문 통과 절차를 분리하되 중단 조건을 먼저 평가한다.
- 데이터 미확보 시: 임의 방 좌표나 이전 수동 좌표로 대체하지 않는다. 소화 시도는 시작하지 않고 일반 대피 기능을 유지한다.

현재 인계 시점에는 이 건물의 원본 FDS와 BIN/SVT 공간·시간 정합을 확인할 자료가 부족하다. 따라서 **소화 동작을 무조건 재생하는 완성 시연 상태가 아니다.** 메타데이터와 실제 위험 데이터의 정합을 연결한 후 건물 안에서 검증해야 한다.

## 2. 기준 커밋과 적용 범위

규칙 참고: [225a1e7ebf498ab0190fad647b5eab15bf8789dc](https://github.com/YOON-JAEYEONG/Fire-Simulation/commit/225a1e7ebf498ab0190fad647b5eab15bf8789dc)의 `YUFS/Docs/NPC_NAVIGATION_V2.md` 및 관련 인지·경로 코드.

이번 작업은 해당 커밋 전체를 이식하거나 병합한 것이 아니다. 기존 `zion-fs`의 NPC·팀별 연결 구조를 유지하면서 다음 원칙을 적용했다.

| 기준 원칙 | 이번 연결 | 적용 범위의 한계 |
|---|---|---|
| NPC가 직접 관측한 연기·열에 근거해 판단 | 가림 검사를 통과한 데이터 표본, 가까운 열·시야 열, 개인별 인지 위험 사용 | 화면 불꽃 픽셀 인식이나 물리적 복사열 모델이 아님 |
| 보지 못한 위험을 미리 아는 경로 계산 금지 | NPC별 관측 기록을 값 복사한 스냅샷으로 경로 검사·비용 계산 | 미관측 영역의 추가 비용 0은 안전 확인을 뜻하지 않음 |
| 비동기 경로 결과와 목적지 정합 | 요청 세대로 오래된 결과 무효화, 원래 목적지 유지, 불완전·위험 경로 거부, 실패 재시도 제한 | 참조 커밋의 모든 복구·군중 조정 로직을 가져온 것은 아님 |
| 경로 모서리를 지나치게 일찍 넘지 않음 | 중간 경유점 허용 거리를 최대 25cm로 제한 | 실제 문 폭·계단·NavMesh 배치 검증은 별도 |
| 순간이동이나 물리 충돌 해제로 통과시키지 않음 | NPC 위치를 강제로 바꾸지 않고 실제 문 회전·기존 이동으로 통과 | 문 손잡이 IK와 고급 군중 회피는 미구현 |
| 기존 모델 계약 유지 | `FYUFSNPCObservation::FeatureCount=28`, 기존 행동 11개의 번호·순서 유지 | 새로운 열 단서는 런타임 판단에만 사용 |
| 정합을 확인하지 않은 데이터를 추측하지 않음 | FDS 메타데이터와 BinaryManager의 정합 확인이 없으면 소화 시작 거부 | 원본·정합 공급 없이 실제 소화 장면을 보장하지 않음 |

참조 커밋의 경보 개인차 전체 모델, NPC 간 관측 기억 전달, 액터 ID 기반 합류 우선순위와 `LocalMovement`의 후진·측방 복구는 이번 변경 전체에 이식됐다고 주장하지 않는다. 현재 관측 기록도 참조 커밋의 8,192셀 구조와 동일하지 않다. 이 구현은 최대 256개 관측 표본과 기본 30초 기억을 사용한다.

## 3. 소화 시도 흐름

```text
FDS 발화 메타데이터 + 정합 확인된 BIN 위험 데이터
    ↓
기존 NPC가 소화기와 발화 단서를 실제로 발견
    ↓
훈련·도구·퇴로·현재 위험 조건 확인 → 조건 실패: 기존 판단 계속
    ↓
설정된 확률로 한 번 선택 → 미선택: 기존 대피 계속
    ↓
소화기 예약 → 집기 → 접근 위치까지 기존 경로로 이동
    ↓
조준·준비 → 분사 표현 / 소화약제 잔량 소비
    ↓
위험·공식 대피·도구·데이터·퇴로 조건 재평가
    ├─ 유지 가능: 계속 시도
    └─ 중단 필요: 분사/예약 정리 → 기존 대피 또는 안전한 경로 미확보 시 대기 판단

어느 단계에서도 FDS/BIN/SVT의 화재 강도를 감소시키지 않음
```

### 발견과 선택

- 발화점 메타데이터를 읽었다는 이유만으로 모든 NPC에게 그 위치를 알려주지 않는다.
- 발화 단서는 기본 탐색 반경 1,200cm, 시야 방향, 벽·바닥 가림 검사와 실제 연기/열 표본을 함께 검사한다. 발화 위치 단서의 초기 기준은 정규화 열 0.20 또는 연기 0.15이다.
- 소화기 가용성·예약 소유권·잔량을 확인한다. 다른 NPC가 잡은 소화기를 공유 소유하지 않는다.
- 기본 최소 훈련값은 0.55이며 정책 에셋에서 조정할 수 있다. 실제 연구에서 검증한 자격 임계값이 아니다.
- `DefaultGame.ini`의 `TrainedPopulationFraction=0.65`, `SuppressionChoiceProbability=0.35`는 시나리오 설계 설정이다. 전체 NPC 35%의 실제 소화 실행을 보장하는 값이 아니다.
- 선택은 조건을 만족한 NPC와 같은 발화 대상에 대해 한 번 판단한다. 도구를 바꾸거나 매 프레임 다시 추첨해 결국 모두 소화하도록 만들지 않는다.
- 선택 비율과 실제 집기·분사 비율은 다르다. 예약 실패, 경로 실패, 위험 상승, 데이터 상실로 실행 전에 중단될 수 있다.

### 접근·분사

- 발화점 주변 약 230cm의 12개 후보에서 NavMesh 투영·동일 층·시야·완전 경로·알고 있는 위험을 확인하고 접근 지점을 선택한다.
- NPC가 발화 좌표 자체로 걸어 들어가는 것이 아니다. 접근 지점에 도착한 후 거리·층·시야를 다시 검사한다.
- 방향 정렬 후 약 1.5초 준비하고 기존 소화기 분사 표현을 재생한다. 분사 중 소화약제 잔량은 초당 0.75 단위로 소비한다.
- 잔량 소비와 분사 표현은 상호작용 진행 상태다. 실제 연소 감소·온도 저하·연기 제거·진압 성공이 아니다.
- 손에 든 소화기 위치 표현은 기존 캐릭터의 손 본/소켓을 따른다. NPC 자체를 순간이동시키거나 별도 소방 NPC로 교체하지 않는다.

## 4. 위험에 따라 시도를 중단하는 규칙

정의는 `Source/YUFS/NPC/Integration/YUFSSuppressionSafety.h`에 모았다. 아래 수치와 가중치는 동작 비교를 위한 **설계 초기값**이며 실제 인간의 소화 지속 시간·반응 확률을 검증한 모델이 아니다.

```text
중단위험 = clamp(
    0.55 + 0.15 × RiskTolerance
         + 0.08 × FireTraining
         - 0.10 × StressSensitivity,
    0.50, 0.72)

시작위험 = 중단위험 - 0.10

현재인지위험 = clamp(max(
    Cognition.PerceivedRisk,
    Observation.RiskPerception,
    Observation.RiskLevel), 0, 1)
```

- 새로 시작하려면 현재인지위험이 시작위험 **미만**이어야 한다.
- 진행 중에는 중단위험 미만인 동안만 유지한다. 중단위험에 도달하거나 넘으면 중단한다.
- 시작·중단 사이의 0.10 간격은 값이 경계에서 조금 흔들릴 때 소화와 대피를 계속 반복하지 않게 하는 히스테리시스다.
- 예를 들어 위험 감수 0.30, 훈련 0.85, 스트레스 민감도 0.50이면 시작 기준은 0.513, 중단 기준은 0.613이다. 0.55에서는 새 시도를 시작하지 않지만 이미 진행하던 시도는 유지할 수 있다. 이것은 계산 예시이지 인간 통계가 아니다.

개인별 임계값보다 우선하는 중단 조건:

| 조건 | 처리 |
|---|---|
| 자기 위치 연기 ≥ 0.70 | 긴급 중단 |
| 자기 위치 열 또는 가까운 열 ≥ 0.65 | 긴급 중단 |
| 인지 상태가 `ImmediateLifeThreat` | 긴급 중단 |
| 행동불능 또는 기어가기 | 소화 중단, 해당 신체 상태 우선 |
| 직원 안내 또는 실시간 공식 방송 | 소화보다 대피 안내 우선 |
| FDS 대상 상실/변경, 도구 소유권 상실 | 해당 시도 중단 |
| 실제 위험 표본을 1초 넘게 확보하지 못함 | 데이터를 안전한 0으로 간주하지 않고 중단 |
| 알고 있는 도달 가능한 퇴로 상실 | 계속 소화하지 않고 기존 안전 판단으로 복귀 |
| 약제 고갈 또는 시도 예산 상한(기본 90초) | 실패/중단 처리, 진압 성공으로 처리하지 않음 |

열 값은 내보낸 바이트를 255로 나눈 정규화 값이며 **섭씨 온도가 아니다.** 가까운 열 감지는 국소 데이터 표본 검사이지 열복사 해석이 아니다.

위험 재평가는 문/도움 상호작용 실행보다 먼저 한다. 따라서 소화 도중 문을 여느라 기다리고 있어도 위험 상승을 무시한 채 소화를 계속하지 않는다. 중단 시 분사를 끄고 도구·문 예약을 정리하며, 오래된 접근 경로 결과가 다시 적용되지 않도록 무효화한다.

퇴로는 완전한 경로가 있고 관측한 위험으로 반박되지 않는지를 검사한다. 건물 전체를 전지적으로 검사해서 안전을 보장하는 의미가 아니다. 경로가 없거나 행동불능인 경우 강제로 달리게 하거나 출구로 순간이동시키지 않는다.

검사한 출구 좌표와 경로를 대피 계층에 넘겨 최대 60초 동안 우선 사용한다. 거리만 가까운 다른 출구로 즉시 바꾸지 않으며, 새 위험·경로 실패·목적지 변경·시간 만료 시 이 우선순위를 해제한다. 실제 실패한 출구는 최대 8개까지 10초 재선택 유예를 둔다. 소화 접근 때 낮췄던 이동 속도도 소화 전 값으로 복원하되, 기어가기·행동불능 제한을 우선한다.

위험 데이터가 누락된 프레임은 측정된 위험 0과 다르다. 기존 인지 위험·물리 위험 단계를 낮추지 않고, 근거 없는 연기 피해나 회복을 적산하지 않는다. 경보·공식 안내·주변 반응은 계속 반영하며, 유효한 청정 표본을 다시 받아야 위험 감소·회복 판단을 재개한다.

## 5. 문 열기는 경로의 하위 행동

문을 열기 위해 전체 목적지를 갈아끼우지 않는다. 대피 중이든 소화 접근 중이든 **이미 선택한 다음 경로 구간에 있는 실제 문**만 대상으로 삼는다.

1. 다음 경로 구간 안에서 NPC 폭을 고려한 검사로 문을 발견한다. 모서리 너머의 다른 방 문을 가장 가까운 문이라는 이유로 선택하지 않는다.
2. 손잡이 접근 가능성, 문 자체의 잠금·고온 상태, 다른 사용자의 예약을 확인한다.
3. 이동을 멈추고 손잡이 방향으로 정렬한다. 먼저 예약한 사용자가 있으면 밀고 들어가지 않고 기다린다.
4. 기본 15도 이내로 정렬한 뒤 약 0.35초의 기존 손 뻗기 표현을 거쳐 개방을 시작한다.
5. 문짝만 힌지를 중심으로 회전한다. 문 actor의 원래 배치·식별자는 유지한다. 열리는 방향은 첫 사용자의 반대쪽이며 부분 개방 재개 시 방향을 유지한다.
6. 회전 구간을 최대 2도 간격으로 검사한다. 사람이나 벽이 회전 공간을 막으면 문을 관통시키지 않고 개방을 멈춘다. 경첩/문틀/바닥 접촉에는 작은 검사 허용 여유가 있으므로 실제 맵 충돌 확인이 필요하다.
7. 완전히 열리면 통로를 막던 보조 충돌만 해제한다. **열린 문짝 자체는 계속 물리 충돌을 가진다.**
8. 문 열기 성공 시 원래 경로를 지우지 않고 기존 이동 계층에 돌려준다. 사람과 문을 숨기거나 삭제해서 통과한 것처럼 보이게 하지 않는다.

문을 못 열면 현재 경로 요청 revision에 `Blocked` 피드백을 보낸다. 취소·소유자 상실·거리 이탈에는 예약을 정리하며, 부분 개방 상태를 처음으로 되감지 않는다. 기존 자동 닫힘 동작을 새로 추가하지 않았다. 시뮬레이션 시작 전이나 Pause 중에는 문 개방 시간이 진행되지 않는다.

긴급 위험 자체를 이유로 대피 경로의 모든 문 열기를 금지하지 않는다. 위험한 방에 머무는 선택은 중단하되, 탈출에 필요한 문은 그 문 자체가 사용 가능한지 별도로 판단한다. 다만 잠기거나 고온인 문을 무조건 열도록 우회하지 않는다.

문 동작은 기존 호환 애니메이션을 재사용한다. 실제 손잡이에 손가락이 정확히 맞는 IK, 휠체어·부상자별 문 조작, 밀집 인파의 완전한 문 통행 스케줄러는 이번 구현 범위가 아니다.

기존 대피 안내 상호작용도 전역 FDS 위험 조회로 출구를 고르지 않는다. 안내받는 NPC가 알고 있는 출구와 그 NPC의 관측 기록으로 완전한 경로를 확인한 뒤 대피 판단을 재개한다. 보행 가능성·접촉 거리·같은 층·시야 조건은 유지하며, 치유·부축 운반 기능으로 확대하지 않는다.

## 6. FDS 연결: 두 가지 확인이 모두 필요

상세 계약은 [FDS_IGNITION_METADATA_KO.md](FDS_IGNITION_METADATA_KO.md)를 따른다.

### A. 발화 위치·시간 메타데이터

`Config/DefaultGame.ini`의 `[YUFS.FdsIgnition] MetadataFile`에 검토한 sidecar 파일을 연결한다. 기본값은 비어 있다. `Content` 기준 상대 경로 또는 검토한 명시 경로를 사용할 수 있다.

필수 정보는 원본 파일명·SHA-256, 검토한 발화 ID·기준점·활성 시간, 미터 단위, UE 월드 원점·축·스케일, 시뮬레이션 경과시간과 FDS 시간의 대응이다. 검토 완료 후에만 `alignmentConfirmed=true`로 설정한다.

- 좌표는 이미 UE 월드 cm로 변환되어 반환된다. Volume actor 변환을 다시 적용하지 않는다.
- `SVT 프레임 / 재생 fps`를 FDS 시각이라고 추정하지 않는다.
- 면·영역 발화원에서 어느 점을 조준점으로 삼을지는 FDS 담당자가 결정한다.
- 로더는 원본 FDS 전체 파서가 아니며 SHA-256은 형식만 검사한다. 담당자가 실제 원본 바이트의 해시와 대조해야 한다.
- 이전 `bHasInteractionTarget`, `InteractionTargetLocal`, 시연용 사전 지식 플래그는 호환용으로만 남아 있다. 잘못된 메타데이터의 대체 좌표로 사용하지 않는다.

### B. BIN 위험 데이터 정합

`AYUFSBinaryManager::bDatasetAlignmentConfirmed`는 기본 `false`다. 원본 FDS와 BIN/SVT의 공간·축·단위·시간 대응을 확인한 담당자가 설정해야 한다. 이 불리언을 켜는 것 자체가 데이터를 검증하거나 자동 정렬하는 기능은 아니다.

정합 확인 외에도 요청 위치·프레임의 연기와 열 데이터가 실제로 읽혀야 한다. 읽기 실패·미로드·범위 밖을 맑은 공기라고 판정하지 않는다. 메타데이터만 넣었거나 BIN만 읽힌 상태로는 실제 발견과 소화 진입 조건을 모두 만족하지 않는다.

### 팀원이 제공해야 하는 것

1. 실행 대상 원본 FDS와 해당 BIN/SVT의 생성 관계.
2. 발화원 ID·기준점·활성 시간과 원본 해시.
3. 건물의 알려진 기준점·층 높이로 확인한 좌표 매핑.
4. 시뮬레이션 시계·FDS 시간·BIN 프레임·SVT 재생의 검토된 대응.
5. 실제 목표 방에서 표본과 표시가 일치하는지 확인한 기록.

모두 연결하기 전까지는 소화 시도 시작을 거부하는 것이 의도한 동작이다. 테스트용 합성 좌표를 실제 런타임 설정에 설치하지 않는다.

## 8. 검증 범위와 남은 확인

2026-09-10 Windows / UE 5.7 Development Editor 빌드에 성공했다. 전체 `YUFS.` 자동화 테스트 **35개가 통과했고 실패·미실행은 0개**였다. 31개는 경고 없이 통과, 4개는 테스트 월드/기존 재생 로그 경고를 포함해 통과했다. 컴파일러가 UE 권장 버전과 다르다는 경고도 남아 있다. 경고 없는 빌드라고 주장하지 않는다.

- [최종 자동화 결과 JSON](../../Logs/SuppressionRuleTests20260910_Verified/index.json)
- [최종 실행 로그](../../Logs/SuppressionRuleTests20260910_Verified.log)

검사는 NullRHI 환경에서 수행했다. 기존 Prototype 맵의 에디터 로딩 및 테스트용 월드/합성 표본을 검증한 것이며 실제 건물에서 그래픽을 보며 소화→대피 장면을 확인한 결과는 아니다. 초기 검사에서 발견한 테스트의 옛 문 충돌 가정과 float 허용 오차를 수정했고, 최종에는 헤더 의존 코드를 다시 컴파일한 후 전체 검사를 실행했다.

추가한 자동화 테스트의 주요 목적:

- `YUFS.NPC.Suppression.PersonalRiskAndHysteresis`: 시작/중단 경계, 개인 성향 차이, 인지 위험의 독립 중단.
- `YUFS.NPC.Suppression.EmergencyAndAuthorityPriority`: 가까운 열·자기 위치 열·짙은 연기, 신체 상태, 공식 안내 우선순위.
- `YUFS.NPC.Suppression.RuntimeHeatPreserves28Inputs`: 기존 28개 값·순서 유지와 런타임 열 필드 미포함.
- `YUFS.NPC.Suppression.NoLocalFireEffectsOrFallbackTarget`: 시작/일시정지/재개/탐색/초기화 반복에도 로컬 화염·조명 미생성, 이전 임의 좌표 사용 거부.
- `YUFS.NPC.Interaction.DoorReservationAndCollision`: 예약 독점·취소·재개, 문 회전 장애물 검사, 열린 문짝 충돌 유지, Start/Pause/Resume.
- `YUFS.Fire.FdsIgnitionMetadata`: 메타데이터 형식·축·시간·출처 식별·다중 발화원 선택·실패 후 이전 좌표 사용 거부.
- `YUFS.NPC.Suppression.CancellationRestoresNativeExecution`: 실제 활성 소화 실행기의 위험 중단, 속도·판단 복귀, FDS 재생 불변, Stop/에피소드 초기화, 행동불능 유지.
- `YUFS.NPC.Navigation.Interaction`: 오래된 비동기 응답 거부, 완전 경로·층·모서리, 개인 관측 격리, 제한 재시도, 확인한 퇴로 인계·무효화.
- `YUFS.NPC.UnknownHazard`: 데이터 누락 시 위험 기억 유지, 공식/사회 단서의 계속 반영, 근거 없는 피해·회복 방지.

GitHub 원본 조사에서도 발화점 정합을 확정하지 못했다. 14개 브랜치·51개 도달 가능한 커밋을 확인한 구체적 파일 근거와 입력 누락 사항은 [FDS 연결 문서의 저장소 조사 결과](FDS_IGNITION_METADATA_KO.md#2026-09-10-github-원본-조사-결과)에 기록했다. 이번 작업은 로컬 `zion-fs`의 변경이며 커밋·푸시는 하지 않았다.

**아직 주장하지 않는 것:** 실제 건물 전체에서 모든 NPC의 자연스러운 소화→문 통과→대피를 확인했다는 결론, FDS 표시와 BIN 수치의 일치, 모든 문/계단의 막힘 해소, 전원 탈출, 실제 사람의 행동 비율 재현, 물리적 소화 효과.

맵 검증은 원본 데이터 정합 후 진행한다. `PLAYER`/`OVERVIEW` 자유 관찰에서 기존 NPC가 실제 문을 통과하는지, 분사 후 불/연기 데이터가 감소하지 않는지, 위험 증가 시 분사를 끊고 기존 출구 경로로 재개하는지, Pause/Resume에서 중복 예약이나 동작 진행이 없는지 확인한다. 조건을 만족하는 NPC가 없을 때 소화하는 사람이 없다는 결과도 정상적인 결과로 기록한다.
